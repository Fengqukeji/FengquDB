# 大值争用代办提交：主引擎合入记录

用户授权采用的最终定向方案已合入 `src/paged/core.hpp`、`group.hpp` 和新增的 `buffered_submit.hpp`，并增加正式测试 `tests/buffered_submit_tests.cpp`。主库版本仍为 0.3.2，公共 C/C++ 接口与语言绑定未变。本次更新工作区构建产物，没有重新制作发布 SDK 压缩包。

## 采用范围与性能证据

仅 BUFFERED 普通事务中单条、暂存值至少 4096 字节的完整 put 参与代办。无争用时直接提交；竞争发生后有界处理队列，每笔保持独立 WAL、版本、发布和结果。连续代办在事务之间检查数量、累计日志字节和时间边界：最多 `min(group_max, 64)` 笔、达到 256 KiB 或约 200 微秒即停止接下一笔。单笔事务不可拆分，可能越过字节或时间边界。

SYNC、线程内 I/O 额度、小增量、删除、多键批量及原子条件接口保留原路线。完整私有二进制缓冲与减法裁剪保留。

此前同业务最小对照中，4 KiB 简介、8 线程完整保存的三轮中位数为 29,425 → 37,256.2 次/秒，增加 26.61%；抽样 P99 为 6.22 → 0.57 ms。128 B 简介、8 线程读多写少基本持平。2 秒单线程完整保存中位数下降 3.92%，逐轮有升有降，不能声称所有情况都提升。详见[原型证据及负结果](BOUNDED_SUBMIT_PROOF_20261108.md)。

合入后的 Linux Release 主库与已测最终 v4 原型逐字节相同，SHA256 为 `e9fdbbf5233ae4f18e060a02430c2abb368559d1a1d44fe6e50aa4c871d93e11`，因此复用该性能证据，没有重跑完整业务矩阵。早先数据库对照中“33/39 配置领先”的统计属于早先矩阵，不能表示此次全矩阵已重测。

## 集中验证

Windows 与 Linux 各通过 10 项相关 CTest：BUFFERED 代办、原子所有权、Store、共享库 SDK、维护、I/O 额度、操作、特性、大批量路径、混合文件。

新增正式测试在两种存储布局中检查同键冲突、旧快照、组上限 1 交接、排队取消/超时、组长取消、出队后输入存活及独立发布、后继 WAL 失败与恢复封锁、线程内 I/O 额度，以及 8 线程写入后的版本和重开模型核验。故障测试先同步首笔，建立可靠前缀，再注入后续故障。

ASan/UBSan/泄漏检查通过 BUFFERED 代办、原子所有权和 I/O 额度测试。TSan 的首次运行在进入 main 前因运行时内存布局和 ASLR 权限失败；原始 `validate-report.json` 保持 `ok=false`。重试容器允许运行时处理进程 ASLR，随后实际进入 main 并通过 TSan，记录在 `tsan-retry-report.json`。没有修改宿主机 sysctl。

这些验证不等于真实断电认证或移动平台验证。SYNC 新策略不在本次合入范围。
