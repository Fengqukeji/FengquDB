# 分段物理文件层原型（未接入 Store）

本轮为持续使用时的文件长度问题增加可执行原型，目录为 `build/segment-file-lab-20261107/`。它是独立文件层协议验证，**没有接入数据库、没有采用新磁盘格式、没有主库吞吐或长期空间达标结论**。主工程 114 文件冻结基线保持一致，旧发布包未覆盖。

## 解决方向与不变量

原位稀疏回收能释放物理块，却不减少逻辑尾地址和单文件长度。直接重新分配旧偏移，会破坏页、记录和补丁祖先“引用偏移必须早于父记录”的校验，并可能让旧快照或旧缓存引用读到新数据。该原型保留单调逻辑地址，把地址映射到独立的短名物理段；先解除单个物理文件的长度上限，再将可达性标记证明无引用的整段删除。

- 每个段有独立、不可变的身份头，包含 magic、段容量、代际号、段号、数据库 UUID 和 CRC。保留 64 KiB 头区，便于以后将现有 64 KiB 对齐的稀疏回收区间映射到物理段；本轮尚未接入 punch。
- 主段名称仍为 `g` 加 16 位十六进制代际号和 `.fdb`，后续为 `s<16位代际号>_<8位段号>.fdb`，最长 **30 字符**，全部位于同一数据库目录，不增加目录层级。构造时先检查最长路径，才允许写文件。
- 段容量必须为 64 KiB～1 GiB 内的二次幂。64 位单调逻辑地址和 32 位段号都有写前检查；1 GiB 段的原型地址容量上限为 4 EiB，并非无限。正式默认段容量尚未确定。
- 跨段读取、覆盖和追加拆成实际位置 I/O。缺失段返回错误，绝不因读取失败自动创建零文件。只有顺序追加允许创建后续段；无效几何、UUID 或身份头立即拒绝。
- 新段先写独占短名临时文件、同步身份头，再使用同目录“不覆盖已有目标”的原子发布。不能把未完成的头当作权威段文件；发布不确定则停止写入。旧文件层提供的原子重命名原语可用于此处的普通文件，两个受测平台均实际验证了拒绝覆盖。
- 读缓存与待刷盘文件引用分别有界。读缓存驱逐只释放缓存引用，写者单独保留脏引用；达到脏引用额度时由写者先同步旧段，再释放。读者不承担刷盘工作。BUFFERED 数据可能提前持久化，但不能漏掉以后 SYNC 应同步的文件。
- 文件句柄缓存上限不等于进程所有句柄上限：正在执行的读调用可以临时持有已驱逐对象。原型不对 RSS 或任意数量并发调用作硬上限保证，后续应与现有 pin/并发预算协调。
- 整段删除需要上层先证明不可达，且所有旧读者 epoch 已退出；拒绝主段、当前尾段及仍有脏引用的段。删除不会改变逻辑大小。该证明目前由原型调用契约提供，**尚未与 ReclaimSession 的引用闭包连接**。
- 提供恢复专用的尾部截断，先校验将删除段的身份，再截断、移除后续段并同步目录；失败后停止写入。扩展截断当前只支持现有尾段内的稀疏零扩展，不支持跨缺失段的任意稀疏增长。它不是宿主可随意调用的业务数据库接口。

上述方案保留完整私有二进制缓冲的减法裁剪：改变的是文件地址映射，既有值缓冲、补丁和页编辑不需要为了分段而重复拼接。

## 本轮审查修正

1. 最早草稿将 dirty 状态仅放在读缓存节点中。若读者驱逐正在写的节点，之后的 sync 可能遗漏该文件。这是代码审查发现的风险，未宣称已由旧版运行复现；在正式验证前改为写者独立、有界地持有脏文件引用。
2. 直接在最终名称写新段头，会让写失败留下无法验证的权威文件。现在同步临时身份头后才排他发布；注入跨段写失败时，较早确认的数据保持可读，失败的新段不以正式名称出现，尾部按调用者已确认边界回滚后可继续跨段写入。
3. Linux 首次编译暴露 Windows 标准库间接包含掩盖的 `<thread>` 缺失，已改为显式包含，并整理循环作用域。失败编译日志和清单保留为 `initial-*`；这是编译问题，未进入数据库或文件协议运行。

## 已完成验证

最终源码及直接依赖由 `validation-manifest.json` 固定，Windows 使用同一最终 C++ 源码。`source-evidence.zip` 含原型、脚本和直接依赖，压缩包完整性检查通过，SHA256 为 `7056d31b83b12081b5507d91bac0e37ed7482299dfc1bd2722fb960043b08392`。`final-audit.json` 核对源清单、二进制、物理文件大小及资源清理。

**Windows 原生四组通过，Linux ASan/UBSan 含泄漏检测四组通过；Linux TSan 三组通过。** 这是独立可执行文件的分组，不能计作数据库 CTest 或语言绑定已经通过。测试只提供状态文本函数桩，不链接 Store 核心。Linux 受限两核、4 GiB、无额外 swap，没有计时性能比较。

测试故意用 **64 KiB 数据段** 高频跨界；加 64 KiB 段头区后，Windows 与两份 Linux 证据中的单个原生文件最大均为 **131072 字节**，最长文件名均为 **30 字符**。这证明了所测文件层边界，不证明正式 1 GiB 段已验收，也不证明总目录大小长期有界。

TSan 仅重试了 10 次未进入 main 的明确地址布局失败，随后进入并通过；没有跳过已进入测试的错误。TSan 下不执行 fork/强杀组，由 Windows 和 ASan 组覆盖。TSan 编译保留一个已知未使用的强杀辅助函数警告，功能用例没有据此跳过。日志分别为 `windows-test.log`、`asan-test-00.log`、`tsan-test-10.log`，构建和二进制身份见三个 `*-report.json`。两个本轮 Docker 容器及卷均核对所有权后清理，原始数据、日志和 ELF 在 D 盘保留。

## 接入前必须完成

1. 为 SharedFile 提供统一位置 I/O 门面或等价实现，避免现有接受 `SharedFile&` 的恢复/补丁函数绕过分段映射。旧单文件数据继续按原布局读取，新容器必须明确识别；旧程序遇到新容器应拒绝，不能误写。数据库 UUID、段几何及代际在所有打开路径一致校验。
2. 保持代际文件租约的稳定句柄，不能让读缓存驱逐提前释放硬链接别名保护。根目录的最长名称预留须在创建前由现有 24 字符提升至容纳分段名称；保留旧目录读取边界，不能等写出后续段才发现路径超限。
3. 把双根持久边界、恢复截断、检查点尾部与新段发布连接起来；明确进程在临时头、发布、跨段 WAL、任一根同步及目录同步处终止后的恢复结果。原型已同步的原始字节不等于一笔数据库事务已验证原子性。
4. 将稀疏查询/打洞与整段删除连接到可达性标记和跨轮 reader epoch。标记内存须按存活物理段/范围受控，不能仅换成多文件后仍让标记成本跟整个历史逻辑地址空间增长。带历史水位、旧快照及补丁祖先时仍必须保留所需数据。
5. 更新代际清理、备份/增量恢复、统计和异常空间处理的整组文件所有权；不删除不属于该数据库或身份校验失败的同名文件。处理被杀进程留下的未发布临时段，避免长时间积累。
6. 覆盖真实 ENOSPC、内存上限、段号上限附近、持续回收、较大载荷和跨语言最终源码验证，再做正式吞吐/尾延迟/包体比较。Windows 的删除目录持久性及 Android/iOS 仍需按平台验证；进程强杀不能替代硬件掉电验收。

当前完成的是解除单文件长度限制的文件层可行性与故障语义证据，尚未解决主库中的持续回收、总文件数量、地址耗尽、写锁混合回退或最终五方案比较。后续仍按 [长期验收记录](GOAL_ACCEPTANCE_20261107.md) 推进。

后续真实数据库接入已在另一份隔离副本完成阶段验证，连接了 WAL、双根、恢复、回收、整理和全备；新格式身份镜像、两平台 21/21、TSan 六程序、清理故障与未采用边界见 [分段 Store 接入审查](STORE_SEGMENT_INTEGRATION_20261107.md)。本文件保留原始文件层原型的范围，不能混用两份格式和证据。
