# KaLM 小体积模型评估

状态：2026-11-14 结构测量与方案评估。已补充用户的蒸馏完整流程 10 小时上限及当前排除决定。没有修改 WordGame 的模型，没有下载新权重、执行量化、裁剪或训练，也没有得到小模型的实测召回率。

目标：评估将 WordGame 当前 KaLM 权重缩至约 50 MiB 或更小的路线。模型权重大小、下载压缩包大小、向量数据大小、推理运行库大小与运行内存分别计量。

## 50 MiB 的约束

保持参数数量不变、只按每参数固定 bit 理想编码时：

| 权重位数 | 仅权重的理想下限 | 加现有元数据/目录后的理想体积 |
| --- | --- | --- |
| 8 bit | 471.15 MiB | 476.82 MiB |
| 4 bit | 235.57 MiB | 241.24 MiB |
| 2 bit | 117.79 MiB | 123.46 MiB |
| 1 bit | 58.89 MiB | 64.56 MiB |

这些是条件性的大小计算，不是已产出的可用模型。实际块量化另有比例、零点、分组和保留高精度张量的开销，所以不能把上述值当成真实 Q4/Q2 文件大小。

50 MiB 的总预算仅相当于约 0.849 bit/参数；若保留现有目录，给权重的预算更低。常规逐权重量化无法在保留当前结构的条件下达到目标。这个结论不排除通过稀疏编码、低秩分解或改变结构继续减少参数和信息量。

公开量化实现中的 IQ1_S 约为 1.56 bit/权重，Q1_0 约为 1.125 bit/权重，均不是没有额外开销的纯 1 bit；支持与可用性还取决于运行库版本、架构和校准数据。不能将其他大模型的困惑度表当成 KaLM 的检索损失。

## 可行路线与建议

| 路线 | 达到 50 MiB 的判断 | 质量与工程含义 |
| --- | --- | --- |
| 直接把现有模型转 Q4/Q2 | 达不到 | 可做风险较小的体积中间档，但不是本目标的解法 |
| 极低 bit 量化 | 单独使用仍不够 | 可能显著改变向量几何；需校准和匹配内核，不能保证小模型收益等同大模型 |
| 裁剪词表 | 单独使用不够 | 可减少较大的词嵌入矩阵；需重建分词映射并保留中文、代码及字节回退能力，不能简单删掉少见行 |
| 裁层、缩窄网络、低秩或结构化剪枝 | 可能组合达到 | 是新结构，通常需要恢复训练；未经训练直接删层不能保证语义空间可用 |
| KaLM 作教师蒸馏小学生模型 | 本轮排除，超过当前工程时间预算 | 目标约 2,000万～4,000万参数，INT8 加词表等控制在约 25～50 MiB；效果需要训练后评测 |
| 已有小型中文模型作为对照/学生初始化 | 可找到体积合适的候选 | 不能当成原 KaLM 的压缩产物，也不能拿不同榜单得分直接相减计算能力损失 |

若未来重新研究蒸馏，教师应保留在训练/构建端，最终应用只携带学生。训练语料需覆盖中文任务、英文标识符、源码用途、错误码、操作步骤及环境条件；使用真实相关样本、难负例和一般中文语义样本，避免只记住当前项目。本轮不将该路线作为底座开发依赖。

词表目标和隐藏维度需要与训练方案一起设计；减少输出维度本身不会相应缩小现有模型主体。没有针对嵌套维度训练和评测时，也不把截掉前若干维当作无损压缩。

50 MiB 更小的档位也可以研究，例如更小学生网络或静态/子词向量，但应把它们作为新模型档位分别验收，不能承诺保留相同比例的通用语言能力。当前索引基础版不需要模型，模型工作不阻塞现有 PTpma 能力替代。

## 蒸馏时间预算与当前决定

用户约束是超过 10 小时就不采用。这里按从现有推理模型到可交付、可验证的 50 MiB 档位计算，包含训练环境与数据、教师向量、训练、导出/量化和质量验证，不只计算一次 GPU 反向传播。

本机现场条件：RTX 5090，32,607 MiB 显存，约 93.6 GiB 系统内存，Ryzen 9 9950X3D。检查时显存约 30,051 MiB 已在使用；没有中断其他任务。WordGame 的现有环境没有 torch/transformers/datasets/accelerate 等训练组件，观察到的 Comfy 进程环境也没有可直接导入的 torch；这不等于已经普查整机所有环境。已有 GGUF 推理资产不等于已有完整蒸馏流程，尚无本项目准备好的蒸馏训练集和训练脚本。

对通用中文/英文代码/操作经验目标，暂以约 50万～100万段训练文本、2～3 轮训练和一次导出/效果复核作工程预算起点；这是规划假设，不是理论最低样本数，也不是质量保证。单次小规模定向实验可能数小时结束，不能用它替代通用交付验收。

在可使用 GPU 的前提下，完整工作按约 **12～24 小时工程预算**安排，风险主要来自数据准备、教师向量生成、候选调整和导出验证。该区间是规划估算，不是本机训练实测；不包含等待其他 GPU 工作结束，也不承诺所有蒸馏必然超过 10 小时。

可复算的敏感性示例：100万段文本在 100/50/10 段每秒的教师吞吐下，分别约 2.78/5.56/27.78 小时；100万段、batch=64、3轮约 46,875 步，每步 0.1/0.5 秒分别约 1.30/6.51 小时。这些速率是情景输入，未经测量，不能直接套用已有日志中的冷启动时间。环境、校准、重试和独立效果评测还需额外时间。

因此当前按用户预算 **不采用教师蒸馏，不启动长训练**。理由是完整交付预算超过上限、现有证据不能保证 10 小时内得到合格候选，不是已经实测出固定训练耗时。

后续优先比较已有小型中文/多语言编码模型及无需训练的 INT8 转换，作为独立模型候选；现有 KaLM Q8_0 保留为效果基线。小模型切换使用新模型空间身份并重建向量，不直接覆盖 WordGame 当前模型。权重、Tokenizer、CPU 推理运行库及其依赖分别计量，不把权重小于 50 MiB 说成整个 SDK 小于 50 MiB。

## 为什么目前不能给“能力下降 X%”

体积下降约 90% 不意味着质量下降约 90%，也不能推出只损失 5%。还没有本模型在 50 MiB 下的可运行候选和同语料评测，因此当前没有可信的 KaLM 极限压缩损失百分比。

“能力”应拆成：词法定位、中文语义、英文/代码标识、经验相关性、强过滤后的相关性及长文本片段。记录身份、修订、权限、适用环境与删除语义必须完全正确，不归入可接受的模型精度损失。

首轮用约 30～50 个经核对答案的代表性问题，以已有 Q8_0 为基线，固定语料、分段和预处理，使用精确向量搜索以隔离 HNSW 近似误差。先筛明显无效候选，再扩大独立留出集；这么小的样本不适合宣称“只损失 1%～2%”。

分别测量语义 Recall@8、NDCG@8、中文/代码子集和端到端混合检索效果；ANN 再单独与各自模型的精确向量结果比较。保留模型身份、输入、相关性标注、原始排名与校准/训练数据来源，评测样本不能同时用于校准或训练。

损失的相对定义示例：基线 Recall@8 为 90%，候选为 81%，则下降 9 个百分点、相对损失 10%。这是计算说明，不是实测结果。建议先以“主要业务子集 Recall@8/NDCG@8 相对下降不超过 5%～10%”作为可讨论的验收预算，不能写成已有结果。

吞吐、冷启动、热延迟、P99、内存、权重与 CPU/GPU 运行库体积另外报告；低 bit 在某些 CPU 上可能因解码内核变慢。压缩下载包再解压运行也不能解决运行时权重和内存占用。

## 向量压缩与模型压缩分别处理

FP32 的 896 维向量每条占 3,584 字节；INT8 理想数据载荷 896 字节，加量化参数；二值向量理想载荷 112 字节，加元数据。这些减少资料库中的向量占用，不会把生成它们的 506 MiB 模型缩小。

向量量化必须确定范围/校准、处理离群值，并单独验证召回与重排；不能根据内存压缩倍数推断检索损失。
