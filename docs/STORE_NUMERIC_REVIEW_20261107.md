# 数值边界审查与验证（2026-11-07）

本批检查影响数据一致性的长期编号、集合计数、整数、期限和 Java 版本表示。规则见 [数值上限](STORE_NUMERIC_LIMITS.md)。这些边界通过合法文件/内存夹具直接构造；未声称真实运行了 2^64 次操作，也不以有限夹具代替长期生产运行。

## 发现与修复

生产旧 DLL 的确定性复现保存在 `build/store-limits-20261107/repro-before/report.json`。先正常保存并检查点，再在独占关闭的测试文件中将选中根块序号改为 UINT64_MAX 并重算 CRC：

| 阶段 | 旧实现结果 | 数据文件字节数 |
| --- | --- | ---: |
| 构造完成 | 原记录可读 | 12836 |
| 新写入 | 竟然成功确认 | 12964 |
| 检查点 | 返回 LIMIT，已追加页 | 13143 |
| 重开 | 返回 LIMIT，再次追加页 | 13322 |

正常文件的大小限制会更早约束自然增长，这不是声称普通负载很快就会出现此状态；但 API 在数值极限或不可信磁盘状态下也不应确认无法恢复的写入。

现将序号检查前移：真实提交必须留有恢复检查点序号；显式/自动检查点在折叠写页之前检查；恢复在完整扫描后、截断或追加原文件之前检查。耗尽但没有尾部的库仍可读、校验和整理，整理换代后恢复写入。旧实现已留下尾部的耗尽库返回 LIMIT 并保留原字节，没有新增自动修复工具。

集合元数据解码现在拒绝 count>INT64_MAX，避免畸形 UINT64_MAX 计数再自增回绕为零。原本的事务版本、代际、保存点、整数与期限保护保留，并补充边界证据。

Java 的 long 用于携带 uint64 版本位模式，部分订阅/确认、历史、备份、恢复入口却错误要求非负数。本批移除版本字段的有符号限制；JNI 只对相应备份/恢复版本槽允许高位模式，时间、额度、flags 和其他数值仍按原契约检查。接口签名不变，使用 Long.compareUnsigned/Long.toUnsignedString 比较和展示版本。

## 最终验证

证据根为 `build/store-limits-20261107/`，未覆盖发布目录：

- Windows Release 全部 20/20 项 CTest 通过，见 windows-ctest.log；新 paged_limits 包含最终版本的四线程竞争、最大序号重启、失败前文件不变、整理恢复写入、最大代际、保存点、畸形计数、int64 最小索引、非有限 score、TTL 最大时间及期限溢出。
- Linux ASan/UBSan 13/13 项通过，启用泄漏检测和 UBSan 失败退出，见 asan.log 及 asan/source-*.sha256。源码清单保护一致构建。
- Linux TSan 11 个程序通过，包含新 store_limits，见 tsan.log 及各程序日志；只重试 main 前已知地址布局失败，进入测试后的结果没有按布局失败重试。崩溃子进程由 Windows/ASan 覆盖。
- Windows 正式核心库/JNI 的 Java→C#→Python 高版本接力通过，见 windows-bindings/report.json；Java 的 CAS、订阅/确认、持久水位、增量备份与按版本恢复实际跨过 Long.MAX_VALUE。C# 使用 ulong，Python 使用任意精度整数。另核对正负 int64 溢出失败不发布。
- Linux 正式核心库/JNI 的 Java/Python 同类检查通过，见 linux-bindings/report.json。该环境没有 dotnet SDK，未将 C# 算作 Linux 已运行项；ASan 夹具程序仅用于生成边界文件，Java/Python 仍加载正式 Release .so。
- 两平台生产 API 都重做原序号复现：新写入返回 LIMIT、旧记录仍可读、关闭后完整文件字节不变，重开并整理后可继续写入及重启。
- Linux Release 3/3 项共享 C ABI/C++/Store SDK 检查、隔离安装后的独立 C/C++ 消费者及维护/扩展两组 CLI 通过，见 linux-sdk.log、linux-sdk-source.sha256；使用安装后去符号的库。
- 常规三语言独立接口及中文目录共库的 9 条命令通过，见 normal-bindings/report.json，覆盖普通版本的字段索引、事务、订阅、历史与 I/O 预算；Windows 隔离 SDK 的核心/JNI 与当前构建一致，见 windows-sdk-check.json。

初次 Windows 新测试目标编译因缺少 features 头文件失败，并发现测试局部变量遮蔽警告；补齐 include 并改名后构建和以上检查通过。初始日志保留。WSL 构建存在挂载盘的短时文件时钟偏差提示，实际构建与运行均成功。
