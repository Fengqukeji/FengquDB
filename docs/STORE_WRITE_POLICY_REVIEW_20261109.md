# 周期写入接入审查（2026-11-09）

> 历史实现与测试记录，后续内存确认的性能模式已替代其默认提交契约；当前语义见[写入策略](STORE_WRITE_POLICY.md)，新结果见[性能模式复测](STORE_PERFORMANCE_MODE_20261109.md)。

主引擎已接入默认100 ms／1 MiB策略，C/C++、C#、Java、Python可查询、修改、保存和重置。普通同步写在周期模式立即返回ASYNC_REQUIRED（21），严格模式保留原同步路径。配置和异步生命周期契约见[写入策略](STORE_WRITE_POLICY.md)，业务结果见[默认模式复测](STORE_PERIODIC_PERFORMANCE_20261109.md)。没有更新历史发布包。

## 审查与修复

| 范围 | 处理 |
| --- | --- |
| 输入与事务所有权 | submit_put返回前复制输入；事务成功入队时无异常地转移暂存状态并封闭原句柄；保留原快照依赖及期限 |
| Core生命周期 | 提交凭据持有外部Core所有权；写线程先释放私有事务，再报告完成，避免最后一个Core引用在自身写线程析构 |
| 完成通知 | 完成标记、等待及通知共用队列锁；审查修复notify_one造成多个等待者无法全部唤醒的问题，改为notify_all，并加入同凭据双等待者覆盖 |
| 配置切换 | 阻止新接收、排空旧队列及严格提交、可靠发布配置后应用；I/O期间释放接收锁，新异步入队可返回LOCKED |
| 配置失败 | 保存前失败保留旧活动策略；发布不确定返回COMMIT_UNKNOWN，记录未确认保存状态，不能因参数相同忽略重试 |
| 队列与关闭 | 数量及估算字节均有限额；取消唤醒相关前缀；Sync/检查点/正常关闭排空；提前关闭未完成凭据等待，文档明确UI先await/poll |
| 可靠性 | 复用原WAL、刷盘、durable水位、发布顺序；刷盘失败返回COMMIT_UNKNOWN并阻止后续写入；不把入队成功当成可靠成功 |
| 维护上下文 | 带调用线程TLS额度/期限的维护保留原受锁路径，后台线程不借用宿主TLS指针；备份及恢复链基底包含WRITE配置 |
| 语言与示例 | 修复Python提交bytearray的类型问题，仅新提交入口支持可变缓冲；C#不为每笔提交创建阻塞线程；Unity基础示例改用Task/await；同步业务示例显式选严格策略 |
| 旧回归 | 旧同步用例显式配置严格模式，不通过测试宏改变产品默认；目录白名单加入WRITE并验证CRC，修正旧文件数断言 |

完整私有二进制缓冲、减法裁剪、共享读取、大/小写入通道及数据文件格式均保留。新增WRITE是目录内40字节配置，不生成深层目录；缓冲模式BUFFERED没有被重新标成可靠周期写入。

## 适用边界

审查及测试没有证明所有硬件、文件系统、移动设备或长时间生产负载均可靠。崩溃点与进程退出不是物理断电；Android/iOS没有真机验收。普通内存中尚未确认的输入不能保证断电恢复。

性能复测发现热点旧快照事务遇到长周期会集中冲突，重试还会继续等待。这是当前提交模型的性能限制，不是数据丢失或忽略冲突的修复理由；已在性能报告完整保留，相关业务可使用严格模式。
