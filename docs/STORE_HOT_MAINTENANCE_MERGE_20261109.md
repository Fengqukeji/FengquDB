# 原子字段命令与提前整理接入记录（2026-11-09）

已将用户选定的两项接入主引擎：受限的多键读/检查/计算/修改整体交给现有写入调度，以及较大镜像复制块配合提前整理。大值和大原子批量方案未接入，默认性能模式仍为 50 ms / 1 MiB。

## 接入内容

新增公开 `fqdb_store_add_i64_fields`，并接入 C++ `add_i64_fields`、C# `AddInt64Fields`、Java `addInt64Fields` 和 Python `add_i64_fields`。命令接收 1～256 项现有小端 int64 字段的增量与结果范围，按输入顺序作为一笔原子事务执行。普通读改写事务的快照、冲突检查和提交接口继续有效。热点调用需要使用新命令，不能把“新命令零冲突”理解成任意旧事务自动零冲突。

命令支持保留 TTL、重复 key、同一记录的多个字段、范围约束、索引约束、排队超时和单次强制可靠提交。示例和完整结果契约见 [原子字段命令](STORE_FIELD_COMMANDS.md)。服务器业务驱动的热点计数与转账已采用正式新接口。

Hybrid 文件首次转换为直接镜像时，无 I/O 预算路径使用临时 256 KiB 复制缓冲；有预算路径保留 4 KiB 推进量。镜像复制、同步、原子发布及旧读者的保护顺序保留。C/C++、C#、Java、Python 启用后台维护后的默认参数统一为 200 ms 检查、32 MiB 最小占用、32 MiB 增长触发。后台维护仍须启用，显式配置继续有效；这些参数与 50 ms 的业务刷盘周期相互独立。

审计确认 WAL、周期提交、预留池、延迟写入、单元文件和写策略源码与修改前相同；Hybrid 的 `sync` 写入路径也相同。本轮没有接入 `pwritev`，没有提高写入字节阈值。

## 代码审查与边界处理

- 命令输入及暂存数据共用每笔事务预算，并同时受数据库总事务预算控制。提交前的私有资源在发布完成通知前释放，失败、超时、约束错误亦释放。
- 在写线程最新视图中建立私有事务，复用现有索引准备、依赖检查、WAL 和发布流程；中途失败不发布任何字段修改。
- 单键计数与字段加减共用有符号溢出检查，覆盖 `INT64_MIN` 增量及上下界。输出只在完整成功后赋值，失败返回零初始化结果。
- 读取字段后先释放读别名，再修改已有私有缓冲，让同一键多项操作继续复用完整二进制和减法裁剪路径。
- 无变化命令不新建版本；强制可靠的无变化命令仍持久化之前的内存写入。发生不确定提交时保留 `COMMIT_UNKNOWN` 语义，不自动重做加减。
- 保留有限 I/O 预算下的可续做能力及文件转换的持久化顺序。新增缓冲在调用结束释放。

首轮 Windows 验证发现新测试辅助函数与系统/标准库名称相撞，改为独立名称；Java 测试将既有 `info()` 数组误当对象访问，已修正。初始失败日志保留，未算作通过。后续原生及绑定测试通过。

两轮交替对照，每个样本 8 秒。修改前采用 1,000 ms / 64 MiB / 64 MiB 维护参数；接入后采用 200 ms / 32 MiB / 32 MiB 和较大复制块。

| 指标 | 第 1 轮：前→后 | 第 2 轮：前→后 |

| 观测调用最大停顿 | 334.7→45.8 ms | 397.2→134.0 ms |

磁盘占用每秒采样，可能漏掉短暂峰值。本轮是最终代码的短时复测；前一轮 30 秒研究用于方案筛选，两者都不替代小时/天级老化验证。
