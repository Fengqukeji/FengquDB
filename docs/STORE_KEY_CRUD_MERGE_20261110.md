# 按键读取、修改与新增的后续优化（2026-11-10）

本轮核对三个高频路径后，接入准备键读取的弱值复用，以及提交仍处于同一不可变视图时省去重复依赖查找。普通按键接口保留原单键弱引用路径；扩大TLS多键记录和额外弱视图缓存的两个候选均未达收益门槛，未合入。

## 三个能力的实际覆盖

| 能力 | 现有与本轮覆盖 | 收益边界 |
|---|---|---|
| 按键读取 | 普通get/get_shared已有弱引用复用；准备键get/get_into新增稳定发布序号下的元数据和弱值复用 | 本轮大幅提升限于复用准备键、缓存值仍存活的读取；普通接口没有新的稳定大幅收益 |
| 修改 | 已有完整私有二进制减法裁剪、多段差量、受限缓冲转移；本轮省去同一视图下重复验证 | 视图变化仍完整验证；转账未保住首测收益，整存修改仅单对小幅差异 |
| 新增 | 已有单命令路径、已验证旧引用复用和WAL头预留；本轮同视图判断覆盖带索引自动事务和普通显式事务 | 带索引新增三轮中位值提高约19.3%；不能推广成所有新增都快19.3% |

没有修改公开头文件、ABI 2、0.3.2版本、文件格式、默认50 ms / 1 MiB或后台维护参数，没有新增流水线、数据库分片及额外强制刷盘。

## 实现与安全审查

**准备键读取。** fqdb_store_key增加一组固定元数据和弱值引用，计入原有准备键pin预算。命中时检查发布序号稳定、TTL有效和时间未回退，在句柄互斥锁内锁定不可变值；然后释放锁并构造共享租约或复制到调用方缓冲。可以避免重复取得View和进入值缓存。没有缓存DTO结果，不强持有载荷或旧Generation，快照解析和最新值记忆分别保存，避免快照读取覆盖最新元数据。

未命中、发布中、序号耗尽、时间回退、删除、TTL或文件代切换均沿正常查找路径核对。缓存关闭时走正常载荷读取。所有记忆字段受既有句柄mutex保护，使用C++17 weak_ptr，不依赖x86内存序、标准库对象布局或新的TLS数组。多个线程可以共用同一个未关闭的准备键。

get_into继续先确认目标容量，再读取或校验冷载荷。审查发现初版在弱值已失效、并发删除发生于回退前时，可能先设置旧required长度，最终却返回NOT_FOUND。最终实现仅在确认可用弱值后执行快路径输出检查，慢路径在重新查到记录后设置长度；定向屏障回归固定复现该交错，确认NOT_FOUND仍输出required=0。初版源码和通过记录单独存档，最终证据均对应修正版本。

**同视图提交。** 仍验证Generation及扩展功能，仍计算索引和唯一约束。在写者租约下，只有old与transaction.base->view是同一个不可变对象，才省去逐条旧引用和范围最大版本查找；此时不存在比捕获视图更新的逻辑修改。指针不相同时，即使只是无关发布，也执行原来的完整点依赖和范围冲突检查。没有按版本号相等猜测，更没有取消并发冲突控制。内部自动事务经常满足此条件，带索引新增和字段修改都能覆盖。

新增回归验证同视图提交、不同视图下缺失键被插入后的冲突、范围幻读冲突及无关发布后仍可提交。准备键回归覆盖发布中和序号饱和、长键、复用目标、TTL与时间回退、删除重插入、快照混用、整理换代、多线程共用句柄、父Store关闭后继续读及重启，包含单文件/分段和缓存开/关组合。

## 确认结果

与上一轮已接入三项安全优化的主引擎比较，使用同一Linux镜像、原生命名卷、CPU 0/2、2 vCPU/4 GiB。性能模式50 ms / 1 MiB，计时段后台维护200 ms、最小整理及增长均32 MiB；无编译或其他测试并跑。

准备键业务驱动预先为相同4096个键创建句柄；接入前后都使用同一驱动、同一准备键API、Zipf轨迹、完整DTO解码和512 MiB业务缓存。准备句柄不缓存业务结果，原生值读取仍需要正确版本。不能拿本表的准备键数据替换普通get的数据。

| 场景 | 接入前中位值，次/秒 | 当前中位值，次/秒 | 吞吐变化 |
|---|---:|---:|---:|
| 128 B简介、8线程、准备键完整读取 | 6,874,600 | 13,346,500 | +94.1% |
| 4 KiB简介、8线程、转账字段事务 | 112,918 | 112,250 | -0.6% |
| 128 B业务载荷、1线程、带索引新增 | 75,002 | 89,464 | +19.3% |

每项三轮约1秒、交替顺序。准备键读取范围为基线6,584,000～6,888,740，当前13,299,300～13,524,600次/秒；P99中位值0.621 → 0.380 μs。新增范围为基线74,793～80,508，当前87,029～97,519次/秒。

转账初测100,631 → 118,226（约+17.5%）才扩大复核，但复核未保住收益；P99中位值1.669 → 2.159 ms，原始样本波动大，不能承诺延迟改善。保留同视图分支的理由包含带索引新增的已确认收益及减少可证明冗余的检查，不把转账初测当作发布成绩。

额外边界各仅一对样本：普通128 B/8线程读取5,107,860 → 5,229,890次/秒；带索引128 B/1线程整存修改209,837 → 221,677次/秒。两项没有重复证据，不认定稳定收益，也没有继续追逐几个百分点。

新增/修改探针通过公开C++ put提交完整Protobuf记录，维护必填唯一fixed64字段索引；计时包含最终Sync。新增逐条创建不同键，修改在4096键间更新版本字段。两个库使用同一编码、请求序列和验证模型，关闭重开后核对全部业务值并verify索引。不能将其较简单模型的数字与完整档案/转账模型混比。

本轮最终18个样本加新增复核6个，共24个有效样本。标准业务样本由独立进程重开、核对全部字段；新增/修改探针关闭重开并全量核对。没有重新测试其他数据库或完整专项矩阵。

## 验证、包体和平台边界

最终源码在Windows、Linux各通过30/30原生测试。两平台C#、Java、Python写策略与准备键/共享缓冲测试通过，包含Python回退、Java强制复制和共享生命周期路径。所有权与read_path回归通过ASan、UBSan、泄漏检查、TSan。

Android NDK 23.1、ARM64/API 24的动态与静态库重新编译通过，加载段满足16 KiB对齐。iOS设备/模拟器CI任务保留，本机Windows未执行；Android/iOS及Unity IL2CPP真机仍未验证。没有新增平台独占指令或系统调用。

Linux外部语言补测首轮使用了Windows绑定目录存放夹具，并缺少部署所需的版本别名，产生无效验证结果；改为Linux原生命名卷、配齐核心库/JNI别名后，Python、Java、C#补测全部通过。原错误报告保留，未计为通过。
