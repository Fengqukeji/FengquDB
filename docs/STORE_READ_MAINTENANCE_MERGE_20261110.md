# 热点读取、字段投影与分片整理接入（2026-11-10）

三项方向已接入主代码：发布序号减少重复引用操作、直接只读投影及准备投影读取器、空间回收前分片转换。C/C++、C#、Java、Python 接口同步更新。默认写入仍为性能模式 **50 ms / 1 MiB**，可靠模式和单次强制可靠写保留；未修改周期刷盘阻塞、WAL、预留池、大值或大原子批量算法，完整私有二进制缓冲与减法裁剪保留。

## 实现与审查

- 发布中使用奇数序号，发布完成后递增到偶数。准备读取器在发布序号未变且 TTL 有效时直接复用自己持有的不可变结果，省掉 View 引用获取。序号耗尽后永久关闭快速路径，避免编号复用。
- 普通最新值读取有每线程一个键的弱引用记忆，仅在开启缓存、键长不超过 256 字节时启用，不暗中持有 Core、View、文件代或强值引用。缓存关闭保留原始读取和 CRC 校验。快照读取不使用最新值记忆。
- `fqdb_store_project` 直接捕获只读视图，不创建事务、占用快照槽或编解码外层命令。原事务投影继续遵守私有写集和读依赖。准备投影读取器保存字段计划，并复用未失效的投影结果；预算、TTL、版本元数据和共享别名约定不变。
- 投影通常只遍历一次外层字段头，合并相邻选中片段，保持字段顺序、重复标签与原始 wire 字节。超过 64 个不相邻片段退回两遍扫描，限制临时元数据。空计划返回空 Protobuf；仍验证完整外层结构，损坏返回 CONSTRAINT。
- 回收前转换每次最多复制 2 MiB，复制块间检查约 2 ms 的合作式时间目标。片间让出写线程，累计镜像数据在写屏障外预同步；镜像转换互斥锁保护预同步与最终句柄退休，源文件读写可继续。最终头记录、文件同步、原子替换、父目录同步和双根提交屏障保留。
- 让出后重新取得最新业务视图并检查历史保留，不使用复制前的旧视图封存回收边界。审查修复了慢路径 TTL 取时顺序，以及源尾部截断后重用时必须回退镜像复制游标的问题。对应测试覆盖原子发布前后、序号饱和、时间回退、原子整批读取、pin 失败、镜像尾部重用与强杀恢复。

2 ms 是复制块之间的检查目标，不能限制单次操作系统 I/O 或最后的同步耗时。普通业务刷盘仍可能挡住调用，符合本轮范围。

## 持续完整保存与整理

八线程、4 KiB、4096 条记录，启用后台整理，两边使用相同 **200 ms / 最小 32 MiB / 增长 32 MiB** 设置。两轮约 8 秒、交替顺序，所有结果最后 Sync 并独立重开验证。逐秒监控完整窗口中的操作最大停顿与物理占用，不含最后未满一秒窗口；P99 与总吞吐覆盖整个计时区间。
