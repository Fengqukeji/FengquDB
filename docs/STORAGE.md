# 存储与 C ABI 契约

> 历史开发记录：下文旧单文件 Database 的代码与接口已删除，项目尚未发布。当前接入使用 [Store API](STORE_API.md)。


下表描述仍兼容 0.1 的文件格式 1；0.2 新增的格式 2 检查点、按键冲突检测和历史保留详见 [0.2 说明](ITERATION_0_2.md)。

## 文件

所有固定宽度整数为小端，CRC 为 IEEE CRC32（非密码学完整性认证）。

| 区域 | 长度 | 内容 |
| --- | --- | --- |
| 文件头 | 32 | magic `FQDBLOG1`；u32 格式版本 1；u32 头长 32；12 字节保留零；u32 前 28 字节 CRC |
| 事务头 | 32 | magic `FQTXN001`；u64 提交版本；u32 载荷长度；u32 载荷 CRC；u32 前 24 字节 CRC；u32 保留零 |
| 载荷 | 可变 | `proto/transaction.proto` 的 Transaction 消息 |
| 事务尾 | 24 | magic `FQEND001`；u64 相同版本；u32 相同载荷 CRC；u32 前 20 字节 CRC |

提交版本从 1 连续递增；空事务不产生日志。每个非空事务至少一个最终操作，同键多次写入合并为最终状态，键按无符号字节序排序。空键和值合法，删除非现存键仍属于写入操作。

载荷已知字段必须使用匹配 wire type；未知字段可跳过。操作类型只能是 PUT/DELETE；未知类型不能悄悄忽略，否则会破坏一致性。未来需要新操作类型时升级文件格式能力。重复标量采用最后一个值；同一事务的重复操作键按内部日志约束拒绝。应用值保持原始字节，核心不解析或丢弃应用的未知字段。

上限：键 64 KiB、单值 16 MiB、单个事务编码 64 MiB；写集使用保守预算，可能略早于编码上限拒绝。文件偏移不超过 INT64_MAX。未设置全库内存上限；历史默认按提交数和编码载荷设限。部署前必须评估数据规模。

## 提交、故障与恢复

准备事务期间的分配及编码均在写日志之前完成。0.2.3 用调用线程驱动单写者队列，逐事务验证涉及键的修改版本，再按顺序写入各自的事务头/载荷/事务尾；可靠模式调用 `FlushFileBuffers` / `fsync` 后发布完整状态。读者只在获取已发布状态时短暂加锁，编码、索引准备、写入和刷盘不持有这把锁。刷盘期间仍可读上一个完整版本。数据库打开时会同步已恢复文件；POSIX 同时同步父目录以持久化新文件名。

队列空闲时立即处理，无人为凑批延迟；I/O 期间到达的并发请求自然合组，每组最多64个请求、256 KiB日志帧，单个超大事务单独处理。同组事务逐一基于前面已接受事务的候选状态检测冲突，保留各自提交版本、日志边界和变更历史，共用设备同步；事务成功返回仍发生在可靠同步之后。故障恢复可恢复未获成功确认的一组中的完整事务前缀，各事务的原子性保持独立，不能把一组当成跨事务原子单元。显式 `sync` 在同一队列中作为有序屏障处理。

准备/排队/执行中的请求最多256个，编码载荷合计最多64 MiB，超过时阻塞等待；这不包含调用方已经暂存的写集、旧快照、索引、wire元数据及空闲缓存，不是全库内存上限。0.3.1起短值批量可使用连续编码，数据库实例在已有队列锁内复用最多64 KiB空闲编码缓冲，准备批次另持有自己的有界编码缓存；大值与增量使用共享片段。写者复用合并缓冲区，其容量可能因分配器增长策略超过256 KiB。

任何写入或刷盘错误使本实例进入只读的恢复必需状态。`COMMIT_UNKNOWN` 的事务可能在重新打开时存在；旧实例仅展示之前已发布状态。`RECOVERY_REQUIRED` 阻止后续事务开始/提交/同步。已有快照仍可读。写前定位失败没有开始本次日志写入，可返回普通 I/O 错误。

恢复先验证完整文件头和逐事务头。物理文件末尾不足一个事务头，或头合法但载荷/尾部不足时，截断到最近完整事务后同步。完整记录的 magic/序号/校验/语义错误直接返回 CORRUPT，不修改文件。文件头被截断视为损坏；不自动把非空文件初始化为空数据库。完整事务即使在提交返回前崩溃也可能恢复，应用必须处理这一正常的不确定窗口。

此策略无法区分所有“尾部丢写”与外部恶意截断。不得外部修改、复制覆盖或用另一个文件替换打开中的数据库。初期只支持本地文件系统的单进程独占使用。

## C ABI

所有入口在 `include/fengqudb.h`；ABI 版本 1，Cdecl，固定宽度状态与计数，UTF-8 路径。`fqdb_options` 必须使用正确 struct_size、abi_version，保留字段为零；不接受未知选项。C++ 异常在边界转成状态。

`fqdb_get` 等复制值，由数据库分配；调用方用 `fqdb_buffer_free` 释放，不能跨 CRT 直接 free。输出缓冲必须是空的，调用前释放之前结果。NOT_FOUND 与空值是不同结果。

`fqdb_snapshot_get_view` 返回借用的只读值，直到关闭快照前有效；不允许写入或释放。迭代行借用切片直到关闭迭代器前有效。快照与迭代器可在数据库句柄关闭后继续读取。未封存事务持有核心引用，数据库关闭后仍可继续操作并占用文件锁；成功、冲突、结果不确定或恢复必需的事务封存后立即释放核心、快照和读写集，句柄仍须关闭。

数据库句柄线程安全；快照不可变可并发读。事务和迭代器须由调用方串行使用。任何对象销毁都不能与同一对象上的调用并发。C# SafeHandle、Python调用所有权/回退租约及Java生命周期读写锁提供各自封装的生命周期保障；调用方仍应明确关闭对象。

范围为无符号字节字典序 `[begin,end)`，空边界表示无界。变化迭代按提交版本再按键排序；游标是“已完整消费的版本”，同版本多行必须全部消费后才能前移。0.2 采用惰性树扫描与固定批次的增量迭代；历史受保留上限控制，过期返回 HISTORY_LOST。固定旧快照/游标会延长相应内存生命周期。

应用手动建立二级索引时，记录与索引键必须在同一事务更新；业务侧负责字段提取、复合键编码与唯一性检查。该原型尚无自动字段索引管理。

## 0.2.2 读取和检查点

`fqdb_get_into`、`fqdb_snapshot_get_into`、`fqdb_txn_get_into` 复制到调用方缓冲区，输出 required。容量不足返回 BUFFER_TOO_SMALL（16），不部分复制；缺失返回 NOT_FOUND 且 required=0，空值成功且 required=0。destination=nullptr 仅在 capacity=0 时合法，required 必须非空。数据库/快照读取不为返回值分配内存；事务读取仍可能为冲突检测读集分配内存。目标须可写且不得与数据库内部借用字节重叠。

检查点先在目标同目录创建独占临时文件，写完并同步后无覆盖地发布。Windows 使用 MoveFileExW(MOVEFILE_WRITE_THROUGH)，POSIX 使用 link/unlink 并同步父目录。失败仅清理本次拥有的临时文件；崩溃可留下 .tmp 文件，确认无导出运行后由维护工具清理，不自动删除未知文件。发布后父目录同步失败返回 COMMIT_UNKNOWN（10），完整目标可能已经存在，应检查目标再决策，不覆盖重试；源库不因此封锁。只有成功返回的导出可直接确认为已完成备份。

## 0.2.3 批量入口与写入统计

`fqdb_txn_put_many(tx, pairs, count)` 在一次语言边界调用中暂存多个键值。切片参数先全部校验；分配/大小错误仍可能留下已暂存的前缀，应用应关闭/回滚整个事务再重做，最终提交始终保持原子性。count=0允许items为空；单个事务/输入数组不得并发修改。C++ `Transaction::put_many` 与 Python `Transaction.put_many` 使用该入口；Python 对旧库有逐条调用回退。

`fqdb_get_write_info` 输出非空成功提交数、成功写入组数、底层write/sync调用数、历史最大组大小和在途请求/编码字节数。write/sync计数包含打开初始化或恢复，用区间差值测量工作负载；组数仅统计成功发布的非空组。pending计数包含已预留预算但尚在编码的请求，不能当成纯等待队列长度。

## 0.3.0 可选增量日志和新句柄

格式3、PATCH操作、8次增量上限、格式2物化导出、准备键/批次所有权、版本查询和NOT_MODIFIED语义详见 [0.3契约](OPTIMIZATIONS_0_3.md)。默认格式与原C ABI保持兼容；reserved目前仅允许FQDB_OPTION_DELTA_LOG位，其余位继续拒绝。

0.3.2按proto3默认值解释检查点seal中省略的零字段。空格式2检查点可以有零字节seal载荷；空事务载荷、空chunk、错误计数/CRC及未完成的seal仍被拒绝。内置导出继续显式编码seal字段，保持旧读取器兼容。事务内重复整值写入可以复用独占缓冲；准备批次合并共享拥有的不可变值，修改时再隔离，调用方输入的生命周期要求不变。

格式3的历史上限同时约束完整物化载荷预算，可能在编码字节仍很少时提前返回HISTORY_LOST；retained_payload_bytes仍是实际编码字节，不表示历史的全部内存。
