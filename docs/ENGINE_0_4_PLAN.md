# 0.4 嵌入式引擎开发记录

范围：超内存存储与受控缓存、在线整理与快速恢复、可靠性验证、自动字段索引与约束、范围事务及保存点、TTL与原生集合、备份与恢复工具。完整SQL、远程服务、账号权限和复制不在范围内。向量存储/距离计算不依赖模型，Embedding生成由业务侧完成，本轮不引入大模型运行库。

本文件中的未勾选项都是未完成的开发或验收内容，不能按已完成能力对外声明。0.3.2 SDK和源码基线保留。旧数据库文件不静默升级。

## 必须保留的性能设计

- 0.3.1完整二进制缓存的减法裁剪：等长覆盖、删除裁剪、变长仅移动必要尾部；共享对象先隔离一次。不能改回逐个拼接未变化片段。
- 页和值缓存按保留分配量计费；磁盘页和值按需加载；热点数据共享不可变字节，避免多层复制。缓存额度不等于整个进程内存上限，事务私有对象、快照和外部固定对象必须另外计费与限制。
- 日志已写出的值字节可直接成为磁盘引用；索引检查点只持有偏移，避免再写一遍大值。
- 内存中只合并有变化的键，按预算批量固化索引；不让每个小写入同步重写整页树。
- 整理流式运行、复制仍然存活的区间，旧快照固定旧文件代际；发布时短暂同步，不能修改旧快照正在读取的页。
- 字段索引仅在相关字段变化时维护；原生集合用独立元素记录和小元数据增量更新，不重写整个集合。
- TTL采用到期索引与分批回收；到期可见性先由读取时间判断，清理不能强迫前台扫描全库。
- 保存点共享事务私有写集，首次修改复制路径；事务范围读需要独立的幻读验证。
- 既要验证吞吐，也要记录P99、缓存/固定内存、写放大、恢复时间及包体；保留负值，不承诺所有工作负载都最快。

## 当前实现记录

随机 I/O、分片预算缓存与二进制页编辑已接入未发布的 Store 源码接口。基础验证覆盖并发位置读写、文件租约、缓存淘汰与持有对象、等长缓存覆盖和按区间裁剪分裂；完整能力边界与验证记录见下文。

新增的页索引采用写时复制：每批只克隆实际修改的完整页，随后在该私有页上覆盖、裁剪，分裂时复制一次完整页再分别减去另一侧。固定长度子页引用只替换对应条目；仅有变化的页按子到父顺序追加一次。索引键视图直接引用完整页二进制，避免常驻另一份键字符串。增量 AVL 索引保留旧根，并用子树最大修改版本支持后续范围冲突验证。

事务日志编码借用不可变大值，仅生成小型操作头；小日志聚合一次写入，大日志按原有字节分段写入。检查点页保存日志值引用，不复制值本身。增量值最多保留 8 层补丁：热数据先复制一次完整缓存，然后在同一个私有缓冲区连续裁剪；冷数据重建补丁时只读取仍存活的原始区间，后续修改复用结果缓冲区。超过深度上限或同一事务反复修改时，暂存层退回完整值记录。公开 TTL 可见性与 expire 接口已经接通，修改到期时间可复用旧值引用；本批已增加到期摘要索引与显式分批清理，自动清理调度待开发。

缓存命中路径维持单分片锁；大对象入缓存时才按固定顺序协调所有分片并借用全局剩余额度。所有分片合计的保留计费不超预算；缓存淘汰不使外部持有的旧值失效。外部值、捕获的增量根、快照数量与事务暂存对象已分别接入预算，页遍历栈和分配器等额外内存不计入整个进程上限。缓存命中同时核对值长度、校验和与补丁元数据。

前一批的页、日志和缓存基础已经接入本轮 Store 源码接口，见 `STORE_API.md`。已接通 C/C++ 与三种语言绑定、受预算限制的内存增量索引和磁盘页树、原子事务、点/范围冲突、保存点、取消/期限、TTL 可见性与元数据修改、共享只读值、快照/游标、检查点及重启恢复。此前 0.3.2 SDK 不包含新接口，尚未发布新 SDK。

恢复使用仅保存变化键的临时页树进行有界溢写；完整日志校验与语义验证通过前不修改原文件。随后修复不完整尾部，再批量合并元数据并同步双根检查点。自动检查点受增量元数据阈值触发，仍持有写入屏障；本批已新增显式在线整理与完整备份恢复，自动整理调度、自动 TTL 清理调度、集合、自动字段索引/约束、增量备份/PITR、旧库迁移以及 Store 组提交还在待办中。未完成条目保持未勾选，不能以局部完成代替七项完整交付。

## 在线维护与完整备份批次（2026-11-06）

本批新增 `compact`、`backup`、`verify`、`restore` 和维护取消，C/C++、C#、Java、Python 同步接通，并提供 `fqdb_store_cli`。API 支持原库并发读写；独立 CLI 需先取得独占租约。详细参数、错误和资源语义见 `STORE_API.md`。这些仍是未发布的 Store 源码能力，不替换 0.3.2 SDK。

## TTL 到期索引与分批清理批次（2026-11-06）

本批完成子树到期摘要、`purge_expired` 的 C/C++、C#、Java、Python 接入和 CLI `purge-expired`。默认每批 1024 键、1 MiB 估算元数据，遵守原有事务/增量预算及 SYNC/BUFFERED 语义。清理是显式调用的原子墓碑事务，文件空间仍由整理回收；自动调度尚未实现。

页树分支复用现有路径增加最早到期摘要，内存增量树同步维护；无 TTL 和未来到期的分支直接跳过。清理不读值、不构建全键常驻堆、不改变二进制减法裁剪路径。跨批只保留一个续扫键和弱代际引用，尾部扫完后回到前部，避免反复扫描已处理前缀，同时覆盖游标前的新增/刚到期数据。每批候选采用普通 OCC 校验，并发替换或续期会使整批冲突，不能删除新值。失败/取消不推进续扫；WAL 写入开始后仍返回实际提交结果。

新构建兼容缺少摘要的旧 Store 页，保守遍历未知分支；写入逐步补齐修改路径，整理可完整重建摘要。新增字段不保证旧开发版 Store 构建向前兼容，必须使用匹配的新库与绑定。单文件 Database 格式及已发布 0.3.2 SDK 保持原样。

## 可选绑定缓冲复用（2026-11-07）
