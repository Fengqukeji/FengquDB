# 当前 SDK 语言调用成本（Windows x64，2026-11-08）

当前 SDK 的 25 条生成、业务接力、接入和成本命令均通过，包含 69 组测量，即 23 个语言/路径组合各三轮。此处是 Windows 宿主上的单调用线程热数据测试，不是 Linux 2 CPU / 4 GiB 吞吐。原生库与当前预览 SDK 一致，核心 SHA256 为 `e57953d80fcbd9ef6e28976db39664b44a7fcb907517afa56fbe40ec488c32d7`。

## 接入建议

重复读取同一键时，保留准备键并复用输出缓冲；多个不同键使用批量接口。C# 的复用缓冲、Java 的直接缓冲和 Python 的固定绑定缓冲均已由实际样例验证。缓冲读取仍会复制数据，收益来自减少分配、编码和跨边界参数处理。并发调用各自持有输出缓冲，绑定期间保持其地址与容量稳定，并按生命周期释放准备对象。

- csharp：9,136,993/秒，相对该语言返回副本路径约 3.02 倍。
- java：7,636,590/秒，相对该语言返回副本路径约 2.98 倍。
- python：967,065/秒，相对该语言返回副本路径约 2.20 倍。

原生准备键/复用缓冲参考为 11,365,800 次/秒。Python 依然有明显解释器、循环和 ctypes/FFI 成本；固定缓冲提高了本次热点读取吞吐，不能声称已消除语言开销。批量返回还包含逐条结果对象构造，实际选择应结合键分布和业务处理量。

业务只需要部分字段时，可结合原生字段投影、索引和事务操作减少返回与解析的数据；业务模型需要完整 DTO 时，使用官方生成代码和对应 Protobuf 运行时。完整接入样例位于 `examples/protobuf/`，包括 C#、Java、Python 及 Unity 桌面桩，SDK 安装后在 `share/fengqudb/examples/protobuf/`。这轮没有测量原生 C++ 的官方 DTO 解析，不能用字节读取数值替代。
