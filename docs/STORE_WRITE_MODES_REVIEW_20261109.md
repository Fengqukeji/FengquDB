# 性能／可靠模式接入审查（2026-11-09）

完成默认性能模式、可靠模式和单次强制可靠写入，并对审查发现的问题修复、复验。当前接口契约见[写入策略](STORE_WRITE_POLICY.md)，正式72样本结果见[服务器复测](STORE_PERFORMANCE_MODE_20261109.md)。

## 实现与审查修复

- 执行与刷盘分离：单业务写线程立即验证、追加内存WAL、原子发布完整事务，普通同步调用等待内存完成；后台在周期／字节阈值到达时同步。读者不经过写队列。可靠写保持先刷盘、后发布和确认。
- 强制可靠前序屏障：覆盖put、delete、patch、条件原子操作、事务、批量和集合命令；强制no-op及空事务同样处理前缀。不会为消除冲突偷换事务原始快照。
- 待写数据独立持有：Hybrid沿用原待写缓冲，direct／segmented代际采用DeferredIO覆盖层。cache_bytes=0及值缓存淘汰均不会丢掉新数据；刷盘时保留不可变块给读者，成功后才释放。完整二进制缓冲和减法裁剪保留。
- 故障状态：后台同步失败或异常设置原子poisoned和write_failure，durable_version不前移，继续读取当前内存视图，拒绝后续新写。已内存成功的数据不能被包装成已可靠成功，宿主外部副作用须自行处理。
- 维护交互：空间回收末尾sync改为持写者锁，防止与DeferredIO追加竞争；带调用线程I/O额度的维护先可靠处理此前业务前缀，避免旧业务误占维护额度。
- 回归修复：首轮Windows/Linux均发现新缓存错误扩展到了显式BUFFERED，影响故障注入、整理及回收；已限定到SYNC底层选项下的性能提交，保留手动同步路径。
- 缓冲边界：批内按完整执行组重新检查周期／字节触发；缓冲上限包含阈值前缀、下一事务与维护空间。外部极大预算使用饱和运算，避免uint64加法回绕后错误封锁数据库，新增UINT64_MAX预算路径验证。
- 模式切换排空旧请求并同步旧前缀，再可靠保存WRITE和应用；关闭正常SYNC库尽力排空刷盘，显式sync用于取得可检查的结果。
- C/C++、C#、Java、Python完整传递可靠标志，配置改为mode枚举。C函数签名改变后全局ABI升2、SONAME升.so.2，绑定主动拒绝旧库；C++普通打开和open_at均检查。库内配置结构abi_version仍为1，不能和全局ABI混淆。
- 更新公共文档及Unity保存示例，移除默认同步接口拒绝写入的过时说明。Unity异步保存可选择forceReliable，默认完成仅为内存成功。

## 明确边界

性能模式可能丢失未同步后缀，刷盘失败后的内存状态不会自动撤销宿主已经执行的逻辑。关键付费调用force_reliable，并在成功后发布外部副作用。正常close无返回状态，不能替代最后一次显式sync错误检查。

可靠返回仍依赖文件系统／设备正确执行fsync或FlushFileBuffers。本轮验证含进程强杀与模拟I/O故障，不是物理断电验收；未完成Android/iOS真机、长时间生产稳态或所有业务的验证。性能数据保留单调用线程与非逐笔刷盘方案相比的差距，不以降低保证或调整并发窗口掩盖。
