# 主引擎合入后的代码审查

审查范围为读缓存预算与共享所有权、小页缓存、双通道并发读写、直接镜像转换、检查点及空间回收的错误处理。修复直接写在主源码，没有新增候选实现或修改 SDK 接口。

## 已修复的问题

1. **预测预留挤掉正在追加的页。** 原代码按已分配的物理页数量保留最后 16 页，预留空间较大时，真实追加页反而在窗口外。后续小写需要重新读取同一页。改为按逻辑数据尾部保留约 16 页，同时清理无效尾部；回归用例先扩大预留，再连续小写，确认原生读取次数不再增加、历史字节保持一致。
2. **检查点和回收没有统一封锁发布不确定的 Store。** 直接镜像转换可能发生在实际 WAL/页写入之前，原来的 `Generation::write_failed` 尚未置位。现在检查点和回收准备阶段遇到 `COMMIT_UNKNOWN` 同样将 Core 标为需要恢复，后续提交、同步和检查点返回 `RECOVERY_REQUIRED`。
3. **已安装直接镜像后的部分入口绕过失败状态。** 原先普通写入、已知 CRC 写入和转换的快速返回分支，可能在 `materialized_` 已设置时跳过失败检查。现在统一检查可写状态；原子发布之后发生的异常统一报告 `COMMIT_UNKNOWN`，不会以一般错误掩盖文件可能已替换的事实。
4. **只读双通道文件可以先暂存修改。** 原先部分写入口只会在最终物理写入时失败，内存视图可能已经改变。现在预备写入、普通/已知 CRC 写入、截断和同步在暂存前拒绝只读句柄，文件长度及写入计数保持不变。

删除了小页文件中已经不再使用的同步尾部成员。持久化协议和正常提交的同步次数未增加。

## 回归与验证

- Linux Release：21 项 CTest 全部通过，涵盖缓存并发与预算、事务、SDK、TTL、索引、历史、Watch、维护、I/O 预算、分段、回收及双通道存储。
- Windows x64 Release：6 项相关检查全部通过，涵盖分页基础/缓存、C++ SDK、维护、I/O 预算、分段及双通道存储。
- Linux ASan/UBSan：新增与既有双通道检查通过，没有内存或未定义行为报告。
- Linux Python 接入检查通过。
- 新增故障注入覆盖“文件已替换”和“直接后端已安装”两个边界，分别从提交、检查点、回收三条路径触发。每次都检查阻止后续写入、要求重开、已确认值保留、未开始的提交不存在，以及恢复后可继续写入。
- 新增只读修改拒绝检查和预留空间下的活动尾页缓存检查；缓存淘汰仍保留原有共享对象生命周期及预算测试。

本轮没有重跑吞吐矩阵，因此不更新上轮的吞吐比值。消除活动页重复读取有原生读取计数验证，不把它外推为固定比例的性能提升。自适应缓存比例、跨库缓存总预算和缓存未命中合并仍属于独立优化项。
