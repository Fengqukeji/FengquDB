# 本轮嵌入式数据库验收记录

本轮软件范围已完成实现、采用、优化审查、有限故障验证、语言调用成本分析和五方案正式比较。最终 Windows/Linux x64 SDK 目录为 `artifacts/sdk-0.3.2-20261108/`，交付说明见 [SDK](SDK_RELEASE_20261108.md)。归档身份、逐成员校验及解包后独立消费者结果以 `build/final-sdk-20261108/` 的最终报告为准。

本轮不包含用户延期的向量检索、全文检索和 RAG/Wiki，也不包含完整 SQL、远程服务、权限、复制及跨进程协作。Unity 可配置持久化根目录，但桌面验证不等于 Android/iOS 或 IL2CPP 真机验收。

## 修正与结论边界

SQLite 的锁等待重试只属于性能对照适配器，等待计入测量；核心和 SDK 不依赖 SQLite。Redis 的 ready 等待、资源探针的字段名及首轮 pwritev A/B 的 SONAME 错误均保留原始失败，再用独立成功记录串联，没有把失败报告改绿。

本次 4 KiB 复制/批量读取吞吐领先五种受测接入方案；256 B 读取、缓冲批量写和部分可靠写仍有 SQLite 或 Redis 领先。峰值是指定环境和并发点的中位数，不是理论极限或普遍全面超越。guest cpuset 不代表宿主物理核心独占；组合方案只协调本基准进程，不宣称跨进程一致性。

SIGKILL、真实资源额度、有限压力与消毒器提供本次软件验证证据；存储设备是否正确执行刷盘、硬件掉电、移动真机和多年生产仍须在部署环境验证。历史开发记录分散在各审查文档；本记录只汇总最终采用的范围，旧阶段的“未合入”不代表当前状态。
