# 缓存与首次复制路径的隔离优化

本批由 CPU 采样和受限 I/O 复现定位瓶颈。隔离副本位于 `build/cache-lab-20261107/source/`，写入队列沿用原主核心。完成验证后，缓存、首次复制和两份回归测试共 4 个文件已按哈希保护合入；原件保存在同级 `pre-merge/`，合入记录为 `merge-report.json`。原发布包保持原样；完整私有二进制缓冲的减法裁剪未改。

## 采样证据

`build/profile-lab-20261107/baseline-profiles/` 保留 6 个用例的 perf.data、平面热点、调用栈、调度计数、源码清单、加载库哈希和完整模型验证。覆盖单线程/8 线程命中读取、8 线程批量读、覆盖、批量写和混合负载，每项 20 秒。全部模型与独立进程校验通过，容器与卷经所有权检查后清理。

采样构建保留 Release O3/LTO，并增加行符号和帧指针。perf 在收到计时开始标记后附加，收到结束标记时请求停止；事件为用户态 cpu-clock，199 Hz。工具与程序合计受限于 cpuset 0、2，2 CPU、4 GiB、无额外 swap。该镜像包含调试工具，吞吐受采样和编译选项影响，仅作诊断，不与正式峰值混合。

命中读取的用户态样本中，值缓存哈希查找约占 21%～23%，页缓存查找约占 4%，LRU 链表移动约占 11%；单条查找还包含约 16%～20% 的 Table 查找。8 线程读取的共享视图加载约占 0.76%。这些是当前样本的平面占比，不能直接外推为去掉某函数后的加速比；完整符号见 `hotspots.json`。

写入期间还观察到整理的复制、目标页读取和解码。20 秒批量写结束时，活动文件为 2246292111 字节，后台整理完成计数仍为 0，最后状态 TIMEOUT。容器出现内存额度下的回收压力，没有 OOM kill。这揭示持续回收仍须解决，不能把短时写吞吐当作稳态。

## 候选改动

缓存将 LRU 前后链接放入已有哈希节点中。标准 unordered_map 的节点引用在 rehash 后保持有效；成功分配节点后才接入链表，淘汰时先摘链再删除。保持精确 LRU 顺序、分片锁、全局预算、借用者独立所有权及退休清空规则。去掉独立 list 节点的分配和移动调用，并相应调整保守元数据计费。计费下降不是进程 RSS 下降的证明，实际内存仍需实测。

首次复制利用 ViewCursor 每键只输出一行的契约：目标在本轮开始时没有根、delta 和条目，便可直接按新键记账，跳过对不断增长的目标索引的反查。增量追赶仍在已填充目标上查找旧值；CRC、额度、取消、期限和发布检查照常执行。

受限 I/O 回归预填 2048 个键，值长 128 字节、delta 64 KiB、缓存关闭，包含删除和过期记录。旧路径触及 2 MiB 读额度后返回 LIMIT：已读 2094664 字节，仅写 91116 字节，复制尚未完成。候选完成整个整理，读取 615593 字节、写入 703804 字节；Windows 与 Linux 计数相同。随后逐键核对、旧快照、继续写入、关闭重开与校验通过。该对照是旧路径未完成时的下界，不将其误算成两个完整任务的精确倍数。
