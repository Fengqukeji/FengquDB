# 原子合组私有事务生命周期审查

本轮在隔离候选中修复内部事务占用快照额度的问题，并减少一次事务堆分配。Windows 与 Linux 消毒器验证通过；并发混合吞吐有所改善，但小值混合负载仍落后原分段版，**尚未采用**。主工程、原 SDK、上一轮候选及已有发布包均未改动。

证据目录：`build/buffered-group-owner-lab-20261107/`。从上一轮已验证的 v2 清单派生 138 文件，仅修改 `core.hpp`、`group.hpp`、`operations.hpp` 和 `buffered_group_tests.cpp`。没有叠加删除文件计数或借用写句柄的实验；0.3.1 完整私有二进制缓冲及减法裁剪保持不变。源码清单、相对 v2 差异、源码 ZIP、全部结果及审计分别为 `source-manifest.json`、`proposal-from-v2.patch`、`candidate-source.zip`、`summary.json`、`final-audit.json`。

## 修复与审查

此前组内每个 AtomicUpdate 准备出的私有事务及 Capture 一直保留到各自调用返回。保留六个普通快照时，八个串行准备的原子操作仍叠加占用快照额度；上限为八即可触发 FQDB_LIMIT。本轮没有提高额度。

- 私有事务改为 `optional<Transaction>`，原位构造，减少一次堆分配。Transaction 不可移动；已核查 AtomicUpdate 的现有使用均为局部构造或引用传递。
- waiter 增加 noexcept 私有清理回调，调用前先取出并清空回调，保证只执行一次。仅原子操作安装回调；普通事务继续由外部调用者持有，保留冲突重试和快照生命周期。
- 组长在 `append_locked` 返回或抛出后立即释放私有事务，包括准备失败和写入失败后中止组的路径。WAL 局部对象此时已销毁，后续发布使用的键和引用已独立持有，不再访问暂存事务。
- 统一完成函数在访问事务前检查指针，兼容已提前释放、准备前失败、无变化及 COMMIT_UNKNOWN。最终状态、日志标量和 AtomicUpdate 本体继续存活到完成通知。
- 沿用 v2 的 queued/done 同步：仍排队时才允许调用线程检查或撤出；出队后等待组长完成。提前清理发生在 done 发布前，调用线程不会同时检查或销毁私有事务。

确定性回归将原有 grouped_control 的快照上限改为八，保留六个普通 Capture、八次累加、版本 4..11、冲突、取消、超时、旧快照与重开期待。另用上限一强制六笔成功、失败及无变化原子请求进入同组，在发布前暂停组长，确认快照和事务额度均已归零，而读者仍看到旧版本；SYNC 再注入刷盘失败，核对 COMMIT_UNKNOWN、写者中毒及重开后继续读取最终值。还覆盖 Capture 创建前额度失败和直接路径准备失败。

## 采用边界与后续

额度修复已经在本候选通过相关回归，但自然合组仍未达到混合吞吐采用条件。下一步先在保留原调度的对照上独立应用和验证私有生命周期修复，再对合组的剩余成本做针对性诊断；不靠提高默认快照额度掩盖问题，不把减少分配直接等同于提升吞吐。

新候选三语言并发、新格式真实 ENOSPC/内存故障、受控长期回收、移动平台及正式五方案最终比较尚未由本批完成。向量检索、全文检索、RAG/Wiki 继续留待以后单独设计。长期目标保持进行中。

后续已从原 SDK 单独派生保留原调度的修复，原版两平台均复现低额度错误，独立修复通过两平台各 22 项、TSan 七程序、108 项模型/独立重开及三语言 24 组合/24 次独立重开。该验证属于另一份源码，具体性能和采用边界见 [原调度额度修复审查](STORE_ATOMIC_OWNER_REVIEW_20261107.md)，不能继承给本自然合组候选。
