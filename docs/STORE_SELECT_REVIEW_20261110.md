# 原生复杂查询接入、审查与性能记录

本轮将类型化组合条件、引擎内过滤、排序/Top N、聚合/分组/HAVING/DISTINCT、字符串匹配、自动选择已有索引及多源等值关联接入主引擎。接口与例子见 [复杂查询](STORE_SELECT.md)。C/C++、C#、Java、Python 共享现有 txn_execute ABI，新增操作 53/54，未增加原生导出函数；接口仍为开发版 0.3.2 / ABI 2，当前源码与绑定须配套构建。历史二进制 SDK 压缩包未更新。

## 实现与审查修正

* 字段路径被编译为树，只解析已用标签，其余载荷直接跳过。复用不可变编译程序与计划，游标不进入语义缓存键；计划校验目录 epoch，私有写路径不复用旧计划。
* 复合等值/IN 前缀与随后范围生成候选区间，残余条件在 C++ 短路过滤；OR 去重、可选索引完整性证明防止重复或漏记录。无安全索引时明确扫描，Explain 和执行统计反映该选择。
* 覆盖索引可以避免加载业务值，纯键查询使用游标元数据。兼容排序的索引可以提前停止，独立排序使用有界堆；哈希关联只构建一次右侧状态。
* 聚合复用连续相同分组，减少分组键编码与哈希查找。只缓存本次请求拥有的分组状态，键字段深拷贝；unordered_map 元素引用跨 rehash 有效，未依赖具体 STL 布局。分组改变仍比较完整键，交错顺序不丢组。
* 缺字段按三值逻辑处理；空 IN、IN 含 Null、LEFT 无匹配、SEMI/ANTI 隐藏右侧字段均有明确语义。大整数比较不先转 double，SUM 溢出报错。
* 模式匹配使用有界 Thompson NFA；编译状态、匹配暂存与工作量受限。LIKE 的下划线匹配完整 UTF-8 码点，Fuzzy 使用窄带码点编辑距离。Regex 点与字符类为字节语义，ASCII 忽略大小写，不提供回溯引用和前后环视。
* 修正并验证了 schema 变更后的缓存失效、事务私有索引覆盖层、非索引字段点读依赖、扫描范围依赖、Record pin 租约、异常后的预算释放和编译分配生命周期。覆盖聚合不读取业务载荷；小 pin 预算的纯键查询可以读取大值记录的键。
* 修正了 HAVING 的非分组右侧字段校验、关联键类别校验、字节比较/复制的工作计费和跨平台条件表达式告警。

普通 CRUD 路径、可靠提交、事务、TTL、快照和原二进制缓冲/减法裁剪继续沿用；默认写入保持性能模式 50 ms / 1 MiB，后台维护参数不变。新查询的临时状态受预算限制，不使用磁盘溢写。详尽资源、类型和语法边界均在接口文档列出。

## 最小机制验证与最终性能

先用一个分组场景验证连续分组复用。Windows 公共 Python 准备查询、8192 条记录、64 组、4 KiB 载荷，独立验证各组人数与整数总和。每版三次短测的中位吞吐由 **386.85 → 485.62 次/秒，+25.5%**。与构建重叠的第一次测量明确标记 invalid，不计入结论。

最终 Linux Release：Docker 原生数据卷，2 CPU 配额、CPU 0/2、6 GiB 容器上限，默认 Store 缓存和写入参数；单调用线程。使用 C++ 准备请求，计时包含返回结果解码和校验。8192 条玩家记录，每条额外载荷 4096 字节；关联另含 128 个主记录和 4096 张订单。每场景三次约 150 ms 短测取中位数，冷启动和建索引不计时。

下表为**本库最终实现的无索引/有索引对照**，相同业务与结果；倍数表示索引路径相对扫描路径的吞吐。

| 查询 | 无索引 次/秒 | 有索引 次/秒 | 倍数 | 候选数量 | 业务值读取数量 |
| --- | ---: | ---: | ---: | --- | --- |
| 职业+等级过滤，按另一字段取 Top 20 | 842.61 | 44,812.70 | 53.18× | 8192 → 26 | 8192 → 26 |
| 按职业统计 SUM / AVG / COUNT | 972.32 | 46,973.90 | 48.31× | 8192 → 128 | 8192 → 0 |
| 全量按职业分组、SUM / COUNT | 602.93 | 713.72 | 1.18× | 8192 → 8192 | 8192 → 0 |
| 玩家与订单等值关联 | 862.40 | 5,160.78 | 5.98× | 4224 → 384 | 4224 → 128 |

初版全量分组的覆盖索引约比扫描慢 10.5%。加入分组复用后，最终覆盖路径比该初版提高约 31.5%，并比最终无索引路径快约 18.4%。此项保留了失败/较慢证据，未只保留更好结果。

整数、键和排序结果按值精确比较。AVG 因扫描顺序变化得到 `28396.999999999996` 和 `28397`，差约 `3.64e-12`。第一次严格比较整个结果二进制因该差异失败，随后改用数值误差界校验浮点列，整数列继续精确校验，原失败日志保留。

旧接口基线为本轮开始前冻结的原生库。原按键读取与显式索引查询各三轮、每轮约 0.5 秒，交替先后次序，固定 4096 条记录 / 4 KiB 载荷和两版相同的 512 MiB 缓存配置；旧按键比较缓冲预先构造。中位数：

| 旧接口 | 原主引擎 次/秒 | 最终引擎 次/秒 | 变化 |
| --- | ---: | ---: | ---: |
| 热点按键读取 | 13,649,000 | 13,774,300 | +0.9% |
| 40 项显式索引查询 | 179,336 | 165,933 | -7.5% |

旧索引查询有回退，尚不能解释为没有性能成本；这轮没有继续追逐小于用户既定 10% 门槛的变化。短测、热缓存、CPU 调度和代码布局均会影响数值，不是所有硬件/数据分布的保证。无选择性的大扫描、任意排序、模糊匹配及高基数组仍可能昂贵，需使用索引、Explain 和预算。
