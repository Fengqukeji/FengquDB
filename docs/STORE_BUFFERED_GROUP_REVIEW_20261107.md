# Buffered 自然合组提交审查

本轮在另一份隔离副本实现自然合组、无争用直接提交和安全的排队撤出。并发单条覆盖吞吐与尾延迟明显改善，但小值混合负载仍回退，受限快照配置也触发了内部临时对象额度压力，**尚未采用**。主工程和已有发布包未更新，0.3.1 完整私有二进制缓冲及减法裁剪保持不变。

证据目录：`build/buffered-group-lab-20261107/`。当前 `source-manifest.json` 固定 138 文件，基于最终 SDK 的 137 文件，只有 CMake、core/group/operations 及新增测试发生变化。没有叠加上一轮删除计数或写句柄借用提案。`validated-v2-source.zip`、`summary.json` 和 `final-audit.json` 保存源码、全部逐轮结果及二进制身份。

## 提交与生命周期

- buffered 在没有排队且可以立即取得写者时直接提交；发生竞争后才自然合组，保持现有最大 64 笔和 1024 个排队请求的边界，不使用 SYNC 的凑批延迟。
- 一个组共享写者和最终发布，每笔仍独立准备、校验冲突、追加 WAL、分配版本和返回状态；读者在发布前继续看到旧状态。没有把多笔请求改称一笔原子事务，也没有把 buffered 改称持久写入。
- waiter 增加由队列互斥保护的 queued 状态。仍在队列中的请求可因取消/超时撤出，更新链表与计数后才返回；已出队的请求必须等待处理结束，避免调用栈和外部参数先销毁。
- 组长等待写者时也检查自身超时，失败后交还组长资格，让后继请求继续。带线程内 I/O 额度的维护继续直接在调用线程执行，避免其他线程消耗其额度。

确定性测试覆盖两种文件布局的逐笔版本、交叉读写冲突、八次原子累加、排队取消/超时、组长超时后的接替、外国 waiter 已追加后继续存活、旧快照和独立重开；SYNC 也执行排队撤出检查。测试把 SYNC 凑批延迟设为一秒，确认 buffered 不受其影响。

## 停顿诊断及其限制

先从经认证的 Ubuntu APT 仓库单独下载 strace 6.19，版本、包 SHA256、原始日志和许可留在 `trace-tools/`，没有修改既有镜像或数据库发布依赖。四项原分段/新候选对照追踪真实 fsync、fdatasync、fallocate，模型和独立重开通过，但吞吐仅约 4.3～4.6 千条/秒，文件不足 28 MB，没有进入原来 64 MiB 维护触发区间。因此此组不能排除 I/O 原因，也不作为性能收益证据。

随后使用独立的 LD_PRELOAD 诊断库包裹真实 libc 读写、同步和 punch 调用，保留返回值及 errno，统计耗时，仅为超过 10 ms 的调用记录明细；每 100 ms 保存线程等待点/系统调用状态。内核源码和受测核心二进制不改变。

四项十秒诊断均完整模型及独立重开通过，原分段约 334740/341160 条/秒、新候选约 485260/489615 条/秒，已达到维护规模；这些带探针数字不能替代无探针正式测量。最长计时区间内 I/O 分别约 67、93、81、78 ms，没有复现此前秒级停顿，不能据此给出停顿根因或认定它已解决。原始 syscall 探针、汇总和线程样本分别在 `probe-*.stderr`、`probe-report.json`、`probe-*-samples.json`。

## 资源审查及采用边界

另用相同 v2 静态内核，只将新增测试的快照上限改为 8，复现了原子操作返回 FQDB_LIMIT（`size/version limit`）。组内准备出的内部事务及 Capture 仍保留到各调用返回，一组会同时占用多份快照额度；这不是持久数据损坏，但不应靠调大额度掩盖。原始测试、构建和输出位于 `snapshot-bound/`。报告解析器起初匹配了不同错误文本，修正为当前 FQDB_LIMIT 状态表定义，保留原报告，没有改变内核或重新给测试改成绩。

后续优先减少这些内部临时对象的分配与保留时间，让原子操作在组长线程完成所需处理后尽早释放，测量对跨线程内存释放、快照压力和混合吞吐的影响；不能在本批成绩上直接声称这一步已经实现。

Windows 候选 DLL 为 864768 B，比原分段增加 1536 B；Linux 未去符号 SO 为 998256 B，增加 3600 B。原主工程 114 文件和 SDK 137 文件逐一哈希一致，两个旧 DLL 未覆盖。新候选的三语言并发接入、当前格式磁盘/内存异常、长期资源、移动平台及最终五方案比较仍未由本批完成，向量/全文/RAG/Wiki 继续留待以后设计。

后续已在另一份隔离源码完成私有事务原位构造和提前释放，快照上限八及单槽回归通过；Windows/ASan 各 22/22、TSan 七程序及 126 项模型/独立重开通过。混合吞吐有所改善但仍有回退，未采用。新结果和源码身份见 [私有事务生命周期审查](STORE_BUFFERED_OWNER_REVIEW_20261107.md)，不能将其验证倒填为本 v2 已修复。
