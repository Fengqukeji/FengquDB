# 普通批读32份档案优化（2026-11-10）

普通批读已接入三项优化：批内复用索引位置、减少Generation所有权计数、合并结果固定预算申请。没有修改50 ms / 1 MiB刷盘配置、缓存预算上限、数据格式或公开API。仍调用普通get_many，返回同样32份档案并完整解码，没有改成准备读取器缓存或DTO结果缓存。

## 瓶颈定位

此前主引擎在128 B简介/8线程批读约25.4万批/秒。普通调用每批生成32个键，逐项查索引、取不可变值、建立结果，再解码32个DTO。

采样单线程调用的阶段平均值约为：生成键0.48 μs，原生API调用4.70 μs，完整DTO解码1.58 μs，释放原生结果0.18 μs。原生调用内部有以下重复工作：

- 页已复用，但相邻键仍分别做完整二分查找。
- 每次通过临时Table查找，都复制并释放同一个Generation的shared_ptr；32条查询反复修改共享引用计数。
- 每加入一条结果都调整同一个固定预算，形成多次共享原子操作；相同额度的resize也会执行零字节归还。

诊断驱动每256次抽样一次，仍保留完整业务和解码。计时包含计时器开销及调度，不能把阶段数值当作精确CPU占比；8线程/2 vCPU的墙钟阶段尤其会受到抢占影响。

证据：[单线程采样](../build/batch32-20261110/profile1-report.json)、[8线程采样](../build/batch32-20261110/profile-report.json)、[诊断驱动](../build/batch32-20261110/fq-profile.cpp)。最终正式对照使用未插入这些计时器的原业务可执行文件。

## 接入实现

**复用查找位置。** 请求内ReadPath原来已保留最多三层不可变索引页，现在再记住页内上一次lower_bound位置。重复键、相邻键、仍在同一排序区间的键先验证位置及相邻边界；不能证明正确时回到完整二分。位置随页、根和Generation切换重置，深层或预算不允许保留页时走原路径。不会因为“上次查过”就跳过数据校验。

**借用调用期间已有的Generation所有权。** View在整次查找中持有Generation，公共lookup无需为每个键再构造一个拥有相同Generation的临时Table。索引页仍由ReadPath或调用内局部shared_ptr持有；返回的是复制后的Ref，没有裸指针逃逸。原有需要长期所有权的Table和游标继续保留自己的所有权。

**合并预算原子操作。** 新建批结果按当前值的实际保留成本，预先申请一小段已计费额度，估计后续最多7行、额外最多64 KiB。预算紧张时重试精确需求；每个值加入结果前都检查并取得足够额度，最后一行发布结果前归还未用额度，异常路径按RAII归还全部额度。返回后的计费规则、64 MiB结果载荷上限和固定预算上限不变。已有读取器的逐项刷新继续按精确需求计费，未改成无限预留。

实现集中在 `src/paged/table.hpp`、`src/paged/view.hpp`、`src/store.cpp`，`src/paged/budget.hpp`只增加当前计费额度的只读访问器。没有引入持久批缓存、写入分片、流水线或额外线程。

## 最小机制对照

隔离候选先做约0.6秒、同业务的最小样本，确认有收益后再接入：

| 方案 | 吞吐 批/秒 |
|---|---:|
| 原生产库 | 252,152 |
| 候选关闭实验开关 | 248,988 |
| 只合并预算申请 | 257,017 |
| 复用查找位置并减少所有权计数 | 280,407 |
| 两项合并 | 311,961 |

这是机制探针，单样本不能代表稳定水平，也不能简单相加各项收益。最终主引擎删除了实验开关，并减少了结果构造和精确更新时的零字节预算操作。

证据：[初步对照](../build/batch32-20261110/pilot-report.json)。

## 最终主引擎复测

与上一轮相同的服务器业务驱动和镜像，Linux原生命名卷、CPU 0/2、2 vCPU/4 GiB、4096份档案、固定Zipf轨迹、显式512 MiB缓存预算，后台维护保持原专项设置。性能模式50 ms / 1 MiB，计时包含完整DTO解码及最后Sync，读负载没有额外刷盘。每个样本独立重开并核对全部业务字段。

128 B简介/8调用线程/每次32份档案，三轮约1秒、交替顺序：

| 指标 | 接入前主引擎 | 当前主引擎 |

## 审查、验证和包体

审查重点为页指针生命周期、lower_bound严格边界、根/文件代变化、批内同一快照与TTL时间，以及预算预留、精确回退、失败和跨线程关闭。

新增正式回归覆盖前进/后退、重复、缺失、页末哨兵及换页；已有随机4096键和预算0/1 KiB/256 KiB路径对照继续通过。新增64 KiB固定预算下“大首值+31个小值”的批读，确认预留不足时精确回退，覆盖普通、快照、事务和准备读取器，以及后缀超额失败与跨线程释放。

最终源码在Windows和Linux各通过29/29原生测试；两平台C#、Java、Python写策略测试通过。bulk_path_tests和read_path_tests通过ASan、UBSan、泄漏检查及TSan。TTL、系统键、空值、缺失、原子发布、父库关闭后的子句柄、整理和文件代切换等已有检查保留。本轮没有Android/iOS真机验证。

Linux stripped SO为867,888 B，增加4096 B；Windows DLL为891,392 B，增加1536 B。公开接口、绑定及ABI不变，实验和采样代码不进入发布库。
