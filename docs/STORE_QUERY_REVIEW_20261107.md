# Store 查询能力与性能审查

本批在 2026-11-06 开始、11-07 收尾，证据目录为 `build/store-query-20261106/`。只更新开发源码与隔离产物，没有覆盖 release-0.3.2，也没有把整个持续目标标记为完成。

完成有序复合索引、前导等值加下一字段范围、正反序分页、完整元组等值、业务值/投影返回和单条字段投影。C/C++、C#、Java、Python 均接入；支持 10 种顶层标量类型。使用方式、限制和兼容边界见 [查询接口](STORE_QUERY.md)。

## 审查与修正

- 索引查询原来无法看到尚未提交的业务写入。现在仅对有相关私有写入的查询建立临时覆盖，共享持久根与预算，将读依赖合回原事务；覆盖条目不进入正式写集。重复修改/查询、保存点回滚和唯一值交换均覆盖，避免残留临时索引污染提交。
- 查询不读取 writer 专用定义缓存，避免并发读写缓存竞争。无相关私有写入不创建覆盖，普通 KV 不启用这些功能。
- 唯一等值保留点读路径；范围查询结果按实际数量增长并计预算。C ABI 在结果编码结束前保持预算拥有者，避免提前释放计费。
- 初次回归出现 Hash 256 条扫描约 8% 回退。分离查询预算状态、隔离查询编译路径，并将集合扫描改为直接从借用游标生成最终结果，去掉中间行数组和内部全键复制。最终交替对比消除了回退，并提高该场景吞吐。
- 投影保留选中 wire 区间，包括重复、packed 与未知嵌套内容；不将业务消息解码后重建。对完整外层 wire 验证，预算只计实际输出。投影仍需读取相应完整业务值并校验 CRC，不宣称列式 I/O。
- 复合字段一次遍历提取，复用既有页树、增量树、TTL 和事务索引更新；字段和 TTL 未变时不重写条目。私有完整值的减法裁剪路径未改动。

Linux 最终 TSan 7 个程序通过，无数据竞争报告，日志保留在 `tsan-final/`。WSL 存在 main 前地址映射失败，仅对此类已知检测器启动故障重试；进入测试后的失败不会自动重试。崩溃子进程由 Windows/ASan 覆盖，不以 TSan 跳过的子进程声称通过。

官方 protoc 36.2 编码 `proto/store_query.proto`，带 packed 投影字段的请求直接交给 C++ Store 返回正确两行；原始请求保留为 `official-query.bin`。

## 性能与体积

Windows 同机 Release，热缓存、5 组中位数。4096 条记录、每条含 512 字节业务载荷，过滤出同组分数区间内 40 条。扫描方案取主键、排序并核对与索引查询相同的结果；索引方案以公共 C++ API 返回行。结果为 `query-benchmark-equivalent.jsonl`：

| 操作 | 每次查询 | 吞吐 |
| --- | ---: | ---: |
| 全范围扫描、筛选、排序 | 329.46 us | 3035/s |
| 复合范围，只返回主键 | 6.87 us | 145488/s |
| 复合范围，返回完整值 | 17.96 us | 55691/s |
| 复合范围，仅投影字段 1、2 | 17.38 us | 57548/s |

主键场景约 47.9 倍是相对本库扫描实现的特定选择性收益，不是跨数据库结论。值已在热缓存，投影与完整值的 CPU 差异不大；投影的主要收益是减少返回体和跨语言传输。完整性能框架仍须覆盖冷缓存、并发及持久化语义。

旧基准采用同一份可执行文件，各放本批前/后的 DLL，交替运行 5 轮，见 `regression-scan/comparison.json`。最终 Hash 256 条扫描吞吐为原来的 1.236 倍，1 MiB 扫描为 0.996 倍；其余 KV/Hash 点读及缓冲新增场景约在 ±2% 内，256 KiB 命令读取为 1.086 倍。较早中间结果保留在 regression 与 regression-final，不作为最终结果。

Windows 核心 DLL 从 717824 增至 745984 字节，新增约 3.9%；不是整体包体缩小。Android strip 后相对上一批 783528 字节增加约 3.1%。发布 0.3.2 DLL 的 SHA256 保持 `3411f07db33140f7b7fc1a479d36c51b862460295680194462489a39d07ee9c9`。
