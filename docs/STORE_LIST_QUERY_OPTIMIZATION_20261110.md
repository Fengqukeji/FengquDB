列表与条件查询优化（2026-11-10）

已合入主引擎，保留默认性能模式 **50 ms／1 MiB**，没有改动公开接口、文件格式或 ABI。主要收益来自连续读取列表时减少重复点查，以及范围游标减少共享预算的原子操作。条件查询另增加请求内的索引页复用，仍保留原记录的读依赖。完整二进制缓冲、减法裁剪和可靠写入保证沿用原实现。

以下是相对上一版主引擎的三轮交替对比，单位是**完整接口调用次数/秒**。每次列表调用返回64项；每次条件查询返回40条；每次范围扫描返回4096份档案。不同返回量的行不能直接横向比较。

| 场景 | 上一版中位吞吐 | 本版中位吞吐 | 差异 |
|---|---:|---:|---:|
| 连续读取64项列表，单项128 B | 57,803 | 132,345 | **+129.0%** |
| 条件查询返回40条完整档案，单份约4 KiB | 44,094 | 50,726 | +15.0%，有明显波动 |
| 条件查询返回40条的两个字段 | 72,368 | 78,890 | +9.0%，有明显波动 |
| 范围游标读取4096份档案 | 4,302 | 4,754 | **+10.5%** |
| 条件查询只返回40个主键 | 198,732 | 193,229 | -2.8%，复核未重复回退 |

列表64项的三轮提升分别约129.5%、136.5%、99.9%，范围扫描分别约10.4%、9.2%、11.6%。这两项的收益方向一致。完整档案查询和字段投影都保留了较慢样本：例如上一版完整值查询有15,803次/秒样本，本版投影有37,371次/秒样本；没有删除这些数据。中位数不能消除全部环境干扰，不把15.0%表述为稳定保证，也没有把投影9%的收益描述成超过10%。

额外约2秒短复核中，只取主键为200,307 → 201,621次/秒（+0.7%）；投影为71,451 → 77,513（+8.5%）；完整值为38,261 → 50,955（+33.2%）。只取主键没有证明稳定提速；完整值的收益幅度仍不稳定。没有继续为几个百分点扩大优化矩阵。

边界短测覆盖8、16、32、256项列表，以及关闭业务缓存的字段查询。8项仍走点读，477,898 → 479,391次/秒，基本持平。256项为13,445 → 34,759（+158.5%）。16项首对出现约12%回退，追加反序短测为231,343 → 397,559；32项为116,977 → 245,983。保留两次16项的相反结果，不能仅凭单轮调整算法门槛或承诺全部请求长度都提升。关闭缓存的投影为806 → 860次/秒，主要仍受实际文件读取影响。

列表至少返回16项时，现在按有序位置只定位一次，游标连续读取所需区间；不足16项保留原点读路径。每项仍核对完整键的前缀、长度和预期位置，列表缺项必须报损坏，不能跳过后返回短结果。键校验直接比较片段，避免为每项再拼接完整内部键。结果仍复用不可变值，返回的count仍是列表总长度。

列表读依赖由逐项点依赖改为准确的范围依赖，列表元数据依赖保留。范围内并发LIST_SET会使后续派生写入冲突；范围外且不改变列表元数据的SET不增加无关冲突。私有推入、修改、弹出、保存点和借用结果生命周期均保持。游标pin额度不足、大载荷不能容纳、或事务范围槽用尽时，销毁临时游标、清空临时结果并回到原点读，避免优化引入新的额度失败。

范围游标复用不超过64 KiB的上一项载荷预算，大小不变时不做原子计数操作。超过该界限的载荷在查找下一行前归还额度；自然结束、范围边界结束和异常出口都归还载荷预算。游标对象本身的预算仍保留到销毁。计费没有被绕过，也没有增加常驻业务缓存。

带值或投影的条件查询，在缓存开启且pin额度留有余量时，临时复用最多三个不可变索引页，页保留总额不超过64 KiB。缓存按代际、页位置和读取上界校验，查找位置只是经过排序边界检查的提示，支持反序和任意主键顺序。预算不足时用原查找路径；申请前额外留出最大业务主键载荷的余量。缓存只活到本次查询结束。每份源记录仍登记正常点依赖，因此只改非索引字段、索引条目未变的并发更新，也会被事务冲突检查识别。只取主键依然不加载业务载荷。

本次没有增加SQL解析、流水线、写分片或平台专属指令。使用标准C++17所有权、不可变页和已有预算设施，不依赖STL布局。业务载荷的CRC、TTL、快照和提交检查保持。投影依然验证消息的外层wire；这项优化减少索引定位工作，不能把它解释成取消数据校验或列式磁盘读取。

测量使用公开C++接口，包含结果编码、解码和结果核对；计时后Sync、verify，关闭数据库并重开核对查询、列表和记录。所有轮次都使用同一驱动、4096份档案、显式512 MiB缓存、原生命名卷、CPU 0/2、2 vCPU／4 GiB的既有Linux镜像；后台维护保持开启，200 ms／最小32 MiB／增长32 MiB。每个主样本约1秒，追加查询样本约2秒，没有与构建或其他测试并跑。共48个主引擎有效测量样本，按原样保存；这是有界的热点读场景证据，没有重测SQLite、MySQL、Redis或MySQL+Redis。

Windows和Linux各通过30/30项原生测试，涵盖已有恢复、事务、索引、TTL及预算边界。C#、Java、Python的写入策略、准备对象和共享缓冲接入检查在两平台通过。列表专项及查询测试通过ASan／UBSan／泄漏检查和TSan；TSan查询测试按既有条件排除崩溃子进程，这部分由普通测试和ASan覆盖。首轮失败来自新增测试用公开错误捕获器接内部错误，已修正辅助函数；原始失败日志和当时源码快照均保留。

Android NDK23.1、ARM64、API24的动态库和静态库编译通过，动态库LOAD对齐保持16 KiB。没有在本机执行iOS构建，也没有Android/iOS设备或Unity IL2CPP运行验收。Windows既有编译警告及新测试的一处有符号比较警告不影响上述通过结果；不声称零警告构建。
