# 三项安全优化接入主引擎（2026-11-10）

共用写路径复用、带索引自动事务的私有缓冲转移、预算约束的索引规则缓存已接入主引擎。采用的是接入前[风险审查](STORE_OPTIMIZATION_SAFETY_REVIEW_20261110.md)限定的版本，已删除隔离实验开关；历史原型和失败证据保留在build研究目录，不参与发布库构建。

公开接口与ABI 2、0.3.2版本、文件格式和完整二进制减法裁剪保持不变。性能模式仍默认50 ms / 1 MiB，可靠模式和每次调用force_reliable保持原协议。没有增加写入分片、流水线、额外忙等或额外Sync。

## 接入内容及安全边界

**共用写路径。** 提交保留Generation、扩展能力、读依赖和范围冲突验证；之后统计变更时复用stage已记录的旧Ref。仅version为0视为不存在，删除标记、TTL及空值继续按原规则处理。WAL操作头预留一次容量，减少字符串扩容；编码字段、顺序、CRC和事务边界不变。

**私有缓冲转移。** CommitWaiter新增内部资格标记，只授予AtomicUpdate普通业务命令、FieldUpdates字段加减命令，以及由异步put请求在写线程内新建的事务。带索引时仍执行完整索引计算、唯一约束和依赖验证。普通显式事务、从用户事务提交的异步写集、保存点、游标、预制批次、历史pin及维护/导入请求不因共用提交代码而获得资格。

WAL接收完成后，获准请求释放WAL内部已经复制的小载荷引用；缓存只对256 B至小于16 KiB、capacity比size至多多64 B、数据确实独占的完整私有值移动Bytes存储。其余情况继续紧凑复制。两个尺寸边界是内部搬移准入条件，不是刷盘阈值；不影响写入结果和持久化协议。大值的延迟I/O借用及裁剪后的大容量不会被强行搬移。

新缓存Data在搬移前分配成功；只搬字节存储，不把携带事务Charge的StagedData留在缓存中。CRC重新设置，按缓存Data的实际capacity计费。缓存准入或分配失败仍属于可选缓存失败，不影响已接收WAL。检查use_count只是所有权证明后的第二道保护，不能替代共享写树和线程同步的限制。

**查询规则缓存。** 每个Core最多保留一个已解析、不可变的规则条目，输入schema最大4096 B；规则字符串容量、parts及元数据计入pin_budget。条目随Core释放，不新增长期TLS缓存，也不持有Generation或事务。多个查询通过C++17的shared_ptr原子操作安全发布、读取；不访问写线程专用的rules_cache。

查询仍逐次取得schema、记录依赖并检查可见性。命中依赖准确的不可变schema对象身份；私有catalog写入一律本地解析。删除重建同名索引、旧快照和不同库不会按名称猜测复用。预算或分配不足时继续使用本次已解析规则，不二次解析、不把可选缓存失败升级为查询失败。竞争填充失败的条目仅供本次查询使用并归还预算。

## 回归、审查及跨平台结果

新增cache_ownership回归覆盖四种文件布局/模式组合：单文件与分段文件，各自性能模式与可靠模式。验证带索引自动put及多键字段更新确实经过转移分支、旧快照和共享值不变、事务预算释放、游标间接共享、保存点及预制批次不被消费、大值和裁剪后大容量回退。索引规则回归覆盖预算计费与释放、缓存关闭、同名重建、旧快照、私有schema修改、预算耗尽后的查询回退及并发填充。

| 验证范围 | 结果 |
|---|---|
| Windows/MSVC原生测试 | 30/30通过 |
| Linux/GCC原生测试 | 30/30通过 |
| Windows、Linux的C#、Java、Python写策略测试 | 全部通过 |
| 新所有权测试、完整索引查询测试 | ASan、UBSan、泄漏检查、TSan通过 |
| Android NDK 23.1.7779620、ARM64、API 24 | 动态库、静态库交叉编译通过；动态库三个LOAD段均16 KiB对齐 |
| iOS | 已新增Apple Clang设备arm64及模拟器arm64静态库CI编译任务；本机Windows未执行 |

Android/iOS构建检查加入现有CI，Android同时构建动态及静态库，使用NDK 27.2；iOS任务使用部署目标13.0。CI配置新增不等于任务已在远端运行，也不等于真机或Unity IL2CPP验收。当前未做Android/iOS设备运行和真实掉电验证。

实现保持标准C++17，不硬编码标准库短字符串容量，不依赖move后的源指针、x86内存序或特定SIMD指令，也没有改变平台I/O层。MSVC、GCC及Android libc++已实际编译；Apple工具链仍需上述CI及目标设备验证。

审查确认：可选规则缓存的预算与对象分配都在移动解析结果之前完成；IndexRule移动构造的noexcept由static_assert约束。缓冲转移仅发生在WAL完成借用之后，并以明确的内部资格排除间接共享写集。发布、可靠刷盘和COMMIT_UNKNOWN处理沿用原顺序。

## 最小性能对照及边界

复用前一轮生产库为基线，实际运行当前生产库。相同Linux镜像、原生命名卷、CPU 0/2、2 vCPU/4 GiB、4096份档案、512 MiB业务缓存；性能模式50 ms / 1 MiB。计时期间后台维护保持200 ms、最小整理32 MiB、增长32 MiB。没有与编译或消毒器并跑。

| 场景 | 接入前，业务操作/秒 | 当前主引擎，业务操作/秒 | 单对差异 |
|---|---:|---:|---:|
| 4 KiB，1调用线程，一次整存后一次双字段唯一索引查询 | 145,087 | 153,927 | +6.1% |
| 4 KiB，8调用线程，完整保存 | 83,524 | 80,375 | -3.8% |

各样本约1秒，包含最终Sync，均关闭重开核对全部4096条业务数据；整存采用独立进程核对。混合场景业务操作数为写和查之和，不能与“每秒完成一组写查”的循环数混用。没有三轮交替证据，不据此宣称稳定提速、稳定回退或各能力全面领先；也未重跑竞品和完整性能矩阵。

初次复用旧混合驱动的基线运行返回FQDB_LOCKED，没有产生有效成绩，失败日志、旧驱动及数据库夹具单独保留。调整驱动后，显式准备和收尾校验位于后台维护关闭的阶段，计时前开启后台维护，最终Sync计时完成后再停止维护以校验；当前四个有效样本使用同一修订驱动。未用引擎配置变化替换计时期间的后台维护。失败样本不计入本表。
