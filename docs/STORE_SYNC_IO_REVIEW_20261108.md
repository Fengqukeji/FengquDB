## 否决直接提前填零

源码的现有帧恢复规则要求完整头部通过 CRC 校验。对独立的 1024 条、4 KiB 数据副本主动追加 64 KiB 全零尾部后，公开 C ABI 返回 `FQDB_CORRUPT`（5）；原有效前缀 SHA256 未变，按原长度移除这段测试尾部后，完整模型验证再次通过。该实验用于否决不兼容方案，不是当前库已经支持这种尾部。

因此本轮不采用直接提前填零、放宽 CRC 校验或删同步屏障。后续已完成保持现有格式的 pwritev 隔离实现及评估，结论为暂不采用，详见下文。0.3.1 完整私有二进制缓冲与减法裁剪保持不变。

## 聚合位置写候选：完成评估，未采用

候选只在非 Android 的 Linux 单文件、大于 4 KiB 的 WAL 帧上借用现有片段，通过最多 128 个栈上 iovec 描述符写出；不复制拼接值缓冲。小帧、分段、Windows 和 Android 保持原路径。短写仅推进描述符，EINTR 重试；完整请求先检查 I/O 额度及 INT64 偏移，错误仍进入原恢复协议。

隔离 Release 和 ASan/UBSan 各六项相关测试通过，覆盖 37 字节强制短写、空片段、精确额度和不足额度、部分写入故障、偏移溢出、129 键跨片段事务、旧快照、检查点及全字节重开。候选裁剪后 851504 字节，比基线 847400 字节多 4104 字节；133 个 C 导出相同，无测试导出。

随后使用同一 SHA256 为 `c98894bf31a0fcda3290fb83f63d9500b36f6794a6b04a2e7f90281381a2636f` 的原生程序，交替加载基线/候选，16 个控制场景各三轮，共 96 次完整模型和独立进程重开校验通过。资源为 2 CPU/4 GiB、无 swap，131072 条值，预热一秒、计时三秒；没有并行构建或其他性能测试。
