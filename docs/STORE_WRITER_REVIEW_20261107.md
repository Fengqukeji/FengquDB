# 写者交接诊断与隔离提案（尚未合入）

本记录接续原位稀疏回收实验，区分回收成本、线程交接成本及混合负载回退。以下新增写锁和读者提示均为 `build/` 内隔离提案，不能当作主库或发布 SDK。向量检索、全文检索、RAG/Wiki 仍按用户要求留待以后独立设计。

## 回收量不是单条回退的充分解释

`build/reclaim-cost-lab-20261107/profile-report.json` 保留后台开关对照的 8 项、每项 15 秒结果，均通过模型与独立进程重开：

- 原写锁基线后台开启约 7.8～8.2 万条/秒；关闭约 3.9～4.0 万条/秒。
- 原写锁回收候选后台关闭或开启均约 4.0 万条/秒。
- 候选 15 秒内回收持有写锁约 0.09 秒，其中折叠约 0.05 秒、根同步约 0.03 秒。

因此，不能把约一半的差距简单归因于标记、punch 或双根同步。后续六项 20 秒 perf/getrusage 诊断，原基线后台开启约 8.4 万条/秒、内核约 7.8 微秒/调用、主动切换约 0.45～0.49 次/调用；后台关闭或回收候选约 4.9～5.1 万条/秒、内核约 16 微秒/调用、主动切换约 0.98～0.99 次/调用。用户态每调用成本接近，线程停车和唤醒值得优先调查。

这些是两核、4 GiB、无额外 swap、8 线程、256 字节 BUFFERED 单条覆盖写入的诊断结果；含 perf、符号、帧指针和私有计时，不能直接并入正式吞吐峰值。原始证据为该目录的 `cpu-profiles/host-report.json` 及各项 `report.json`、`flat.txt`、`callgraph.txt`、`stat.txt`。

原 WriterGate **已经使用 notify_one**。`build/writer-gate-lab-20261107/rejection.json` 保留精确源码断言拒绝“把 notify_all 改为 notify_one”这一不存在的改动；不要将该目录旧命名误当作原锁实际用了 notify_all。

## 三状态写锁

`build/writer-atomic-lab-20261107/` 中的提案用 0/1/2 表达空闲、快速持有、持有且有争用。无竞争时 CAS 获取，争用者在 parking mutex 下登记并等待 CV；释放仅在已登记争用时握手通知。唤醒者没有取得或超时时也恢复争用标记，避免遗漏后续唤醒。没有自旋等待、逐次读计数器或平台私有系统调用。

新增 writer_gate 用例包含 12 线程的 lock/try_lock/timed lock 混合、24000 次互斥与非原子 checksum 发布验证，以及 128 轮超时、抢占和唤醒接力；超时直接退出，避免 future 析构掩盖挂死。互斥辅助原子为 relaxed，不替代锁本身的发布保证。

首版主路径 Windows 与 Linux ASan/UBSan 含泄漏检测各 20/20；TSan 的 writer_gate、operations、features、maintenance、watch 五程序通过。回收组合 Windows 相关 6 项通过；修正下述测试租约竞争后 Linux ASan/UBSan 6/6，TSan writer_gate/reclaim 两程序通过。状态字段尾移版另通过 Windows 20/20、Linux ASan/UBSan 3/3、TSan 三程序。隔离构建未启用诊断适配器/JNI，其“20 项”不等于主构建旧“20 项”；合入新增 writer_gate 后主构建应有 21 项。

回收组合首次 ASan 的 `paged_reclaim` 失败为 `database locked`：后台仍启用时结构 verify 要求独占 maintenance lease，允许返回 LOCKED。已保留失败源码和日志；波次中继续核对值，完整结构验证改在 stop_worker 后执行；另加 Held(71) 用例明确验证后台占有租约时结构校验返回 LOCKED、普通读取可用、停止后结构校验通过。修复测试不改变数据库的租约契约。修正后的清单为 `reclaim-corrected-validation-manifest.json`，旧失败报告未覆盖。

带 perf 的六项 20 秒纯写诊断中，三状态锁主路径后台开/关约 11.9～12.7 万条/秒，回收组合约 12.1～12.3 万条/秒，主动切换约 0.09～0.10 次/调用。这证明它在所测纯写负载减少了交接成本，但不能替代未插桩比较。

## 已发布视图引用提示仍未达到采用条件

`build/writer-adaptive-lab-20261107/` 从状态字段尾移版增加 owner-only 快速/保守释放提示。BUFFERED 原子提交观察新发布 View 的额外引用；发现后冷却 64 次写入，读路径不增加计数器。两个模式共用同一所有权状态和 parking 协议。Held(47) 用例验证观察到新视图读者时选择保守模式、静默写入后恢复快速模式。

Windows writer_gate/operations/features 3/3 通过；该版尚未重新完成 Linux ASan/TSan。24/24 项 A/B/B/A、每项 3 秒的模型与独立重开通过：8/32 线程单条覆盖中位数约 +46.48%/+37.99%，混合仍为 -7.39%/-11.14%；32 线程覆盖的 P99 中位数约 14965.682 微秒，原锁约 9650.359 微秒，其中一组候选达到约 22.6 毫秒。该提案未合入。

提示仅观察新视图的短暂引用窗口，可能漏掉仍持有较早视图的读者；目前没有模式命中率或引用分布证据，不能把该假设当作根因，也不应继续凭猜测改冷却阈值。

## 释放 parking mutex 后再通知

原锁在释放 parking mutex 后 notify_one，三状态首版在持锁时 notify_one。`build/writer-notify-lab-20261107/source-main/` 单独调整这一顺序：仍先 release 所有权状态，再通过同一 parking mutex 与等待登记握手，释放该 mutex 后才通知；没有增加读者启发式，也没有改动 acquire/release 内存序。该差异只构成可检验假设，尚不能直接断言它是混合回退根因。

该版 Windows writer_gate/operations/features 3/3 通过，日志为 `windows-test.log`。初次 CMake 配置使用了不适用的选项名，因隔离副本缺少可选工具源文件在生成阶段失败；修正为项目真实开关后成功。原始 `build-00.log` 与失败 `report.json` 保留，没有数据库运行或数据故障。成功阶段为 `retry-build-*` 与 `report-02.json`；初轮过滤器只选中 writer_gate，后补跑正确的三个测试，不能把初轮误记为 3/3。

## 采用边界

本批没有采用任何新的写锁或读者启发式。主工程 114 文件冻结基线保持一致，开发 DLL SHA256 仍为 `5d72256e4fb998c189edb2dff9b21235b9cd9a4277de9c37cf5e443be438c4b3`、790016 字节；旧发布 DLL SHA256 仍为 `3411f07db33140f7b7fc1a479d36c51b862460295680194462489a39d07ee9c9`、281088 字节。完整私有二进制缓冲的减法裁剪保持原有实现。

后续应同时检查未插桩的混合吞吐、批量尾延迟与单条收益；若保留自适应提案，先增加独立诊断的模式命中率和视图引用分布，而非改变读路径或猜阈值。选定版本后再集中完成相关消毒器、SYNC、4 KiB 与持续回收、主构建和语言复验。回收逻辑地址持续增长尚未解决，物理空洞回收仍不能当作长期文件长度有界。最终验收见 [长期目标](GOAL_ACCEPTANCE_20261107.md)。
