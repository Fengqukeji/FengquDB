# Store 历史保留审查与目录边界补强

本批提供持久备份水位和跨在线整理的增量历史保留。接口、流程及兼容边界见 [历史保留](STORE_HISTORY.md)，目录契约见 [Store 目录](STORE_LAYOUT.md)。证据位于 `build/store-history-20261107/`；只修改开发源码和隔离构建，发布 0.3.2 未覆盖，整个持续开发目标仍未完成。

## 实现与审查

命名水位写入既有系统记录，值为数据库 UUID 加版本号；经普通写队列线性化，支持原子固定当前版本。相同水位和解除不存在的水位不写 WAL。C/C++、C#、Java、Python 共用引擎，不维护另一份常驻事件队列。

整理仍生成紧凑的当前状态，只保留慢备份需要的旧代际及原 WAL/补丁引用。检查点原子记录父代际、版本、文件边界和全局历史下限；启动先加载并校验必要祖先，再回收无关文件。缺祖先时失败并保留其他文件，旧快照持有的文件延迟删除。无变化的重复整理跳过空中间段。

源 WAL 必须先于新 CURRENT 持久化，包括 BUFFERED 模式；同步结果不确定时返回 COMMIT_UNKNOWN、停止后续写入并要求重开。完整备份和恢复拥有独立身份，复制来的水位控制记录在新库中不生效，可以同名重新绑定或解除。最多 64 个存储水位、128 个保留代际，元数据计预算；超过代际上限拒绝整理，不丢掉仍需备份的历史。

审查修正了整理最终追赶的两处边界：并发启用集合/索引时同步最新功能标记；并发检查点仅提高时间水位而未增加版本时，也重新持久化目标检查点。保留完整私有二进制缓冲的减法裁剪路径。

目录复核发现短目标名可能对应更长的备份临时目录。现在输出前同时校验最终目录和临时目录的内部文件空间，超限在 mkdir 前返回 LIMIT。新增测试让最终目录合法、临时目录超限且父目录不存在，核对错误类别、无新建目录和源数据完好。该检查仅作用于输出准备，不增加普通读写路径的工作。

## 性能、体积和剩余范围

`regression/comparison.json` 使用同一可执行文件、前后 DLL 交替五轮，未启用历史保留，覆盖热缓存读和 BUFFERED 写。普通点读约保持原水平，缓冲新增存在约 3% 波动，Hash 1 MiB 扫描吞吐约为原来 1.106 倍；不是跨数据库性能结论，也不能据此宣称零损耗。

Windows 核心 DLL 从 745984 增至 764928 字节，增加约 2.5%；最终 Android strip 后为 830608 字节。实际 SHA256 与大小记录在 `binaries.json`。目录补强仅改变备份准备路径，不重跑普通点读基准。发布 DLL SHA256 保持 `3411f07db33140f7b7fc1a479d36c51b862460295680194462489a39d07ee9c9`。

目前历史读取按需扫描 WAL，没有公开变更订阅游标；维护字节预算、真实磁盘/内存限额和长期轮转压力仍待完成。高压缩比多大值补丁物化后仍可能超过既有 64 MiB 事务/归档上限，安全返回 LIMIT，不发布半个归档包。剩余字段操作、可选检索、业务 Protobuf 代码生成示例和三语言性能还在持续目标内；全部能力收尾后才做 Docker Linux 2 CPU/4 GiB 的持久性匹配与吞吐对比。
