# Store 变更订阅与读取复用审查

本批完成进程内按提交拉取变化，C/C++、C#、Java、Python 共用引擎。契约见 [变更订阅](STORE_WATCH.md)，证据位于 `build/store-watch-20261107/`。没有覆盖发布 0.3.2，整体持续目标仍未完成。

## 实现与审查

- 普通写入不复制事件值，不维护另一份常驻队列。订阅按需建立共享通知对象，发布后唤醒等待者；游标保存代际、偏移和版本，按需读取 WAL。交付完整匹配提交或有界过滤进度，显式确认后前进，重复获取共享原生不可变批次，原生或托管分配失败不隐式确认。
- 存活订阅保护未确认历史，确认后不长期固定文件视图或内存索引增量根。取消打断等待和解析。C 以连续行数组返回，三种语言按批跨 native 边界，Java 不逐行调用 JNI。句柄、元数据和值计预算，共用保留代际上限。
- 历史 bit4 与集合命名空间 bit1 分离，仅订阅保留不隐藏旧原始键。集合显式启用仍验证保留前缀冲突。恢复和增量导入采用功能位集合包含校验，防止非法撤销已启用标记。旧开发库需配套升级。
- watch_options 在复制结构前检查长度。Linux SDK 验证脚本将相对输出先绝对化，再传给独立消费者的 CMAKE_PREFIX_PATH；初次消费者查找失败属于脚本路径，修正后的完整脚本与消费者通过。
- Hash GET、List GET/POP/RANGE、Hash 扫描和完整值索引查询直接持有不可变原生值，编码到最终缓冲后释放，去掉中间完整值复制。计算投影仍拥有独立字节。新增用例核对结果在私有写入、提交和整理后编码保持原内容，包含空值。完整私有缓冲的减法裁剪逻辑未改动。

## 性能与体积

未启用订阅的旧基准采用字节相同的可执行文件、前后 DLL 交替五轮，热缓存读和 BUFFERED 写。最终 regression-final/comparison.json 的吞吐比：256 KiB Hash 命令读取 1.941、1 MiB Hash 扫描 1.197、256 条扫描 1.084，原始 KV 命中/未命中 1.001/1.000。KV/Hash/Set 缓冲新增为 0.982/0.965/0.971，仍低约 2%～3.5%，不承诺零损耗。这是特定场景回归，不是跨数据库结论。

初轮短负载部分轮次吞吐跨度超过两倍。预热、固定 CPU 2/18 和拆分接口探针均保留。探针确认热命令读取没有额外磁盘 I/O，不据此断言已确定所有时延差异的根因。可以确定的是中间复制已删除；最终完整负载的进程峰值私有内存由 9588736 降到 8912896 字节，约低 7%，属于进程累计峰值，不是单操作占用。

游标 I/O 用例先写 512 笔 4 KiB 旧提交，随后五次新增小提交各自读取低于 8 KiB，证明位置续读；不代表所有过滤、冷缓存和跨代际场景上限。

Windows DLL 从 764928 增至 783872 字节，增加约 2.5%；相对添加订阅早期实现减少 1024 字节，不宣称整体包体变小。Android 最终 854072 字节。大小及哈希见 binaries.json；发布 DLL SHA256 仍为 `3411f07db33140f7b7fc1a479d36c51b862460295680194462489a39d07ee9c9`。
