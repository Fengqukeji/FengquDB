# retained2 连续元数据与按字节分流原型

后续已整合进主源码，见 [主引擎整合与实测](STORE_ENGINE_MERGE_20261108.md)。本文保留原型当时的容量限制、源码固定点和性能记录，不作为当前主引擎状态。

本轮以 retained2 为基础，保留小写的四副本页布局和单次同步协议，将连续脏页描述、工作缓冲复用与大块顺序追加组合成新的研究候选。没有采用上一轮的分离页头布局，也没有替换主引擎或 SDK。最终源码固定在 `build/arena-retained3-20261108/final2-source/`。

## 行数、字节数与切换点

32 条只是基准测试的输入，不是事务接口的固定条数。16、32、180 条均完成原生写入及独立重开验证；实际仍受事务大小、内存预算和研究原型容量限制。

最终候选的研究默认阈值为 **32768 B，即 32 KiB**：

| 一次同步提交中暂存的实际数据字节 | 路径 |
| --- | --- |
| 小于 32 KiB | retained2 冗余页日志 |
| 大于或等于 32 KiB | 自校验的顺序追加日志 |

普通事务时，这些字节包括完整 WAL 的键、值、元数据、头尾和校验；不能仅按 `条数 × 值大小` 判断。并发提交组和 BUFFERED 最终同步可以包含多笔完整 WAL，按此次同步实际积累的总量判断。路由不是把一笔事务拆到两个通道。

强制两个通道的交叉测试表明，32 条、值为 768 B 时，实际 WAL 约 26,337 B，小通道约 31,592 条/秒，大通道约 26,261 条/秒；值为 1024 B 时，实际 WAL 约 34,529 B，小通道约 19,516 条/秒、大通道约 24,448 条/秒。因此选择两者之间的 32 KiB 作为当前候选值。

边界验证还包含：180 条 × 128 B，实际 WAL 32,645 B，走小通道；180 条 × 129 B，实际 WAL 32,825 B，走大通道。两者的净值数据都不到 32 KiB，这直接说明序列化开销不能忽略。

这不是跨设备、跨条数和所有负载的数学最优点。记录条数还会影响索引处理和编码开销；缓存状态、存储设备、同步模式及并发也会改变交叉位置。研究参数 `FQDB_RESEARCH_ROUTE_BYTES` 可在打开库前配置，零表示强制大通道，足够大的值可用于强制小通道对照，尚未加入正式 SDK 配置。

## 结构与恢复协议

小通道沿用 retained2：每个 4032 B 逻辑页对应四个分离的 4096 B 单元，更新两个较旧副本，保留上次确认的两个。脏页描述改为连续 vector，收集页号后排序，并复用提交工作数组；没有改成上一轮的页头/数据体分离布局。

分流层将逻辑文件的写入、截断组成完整校验记录，加入跨通道唯一、递增的提交序号。每次 sync 的全部操作进入一个通道，执行一次持久化同步后才发布原有 Store 视图。大通道是当前主引擎采用的顺序追加思路，复用 NativeFile 和 RecordFrame，不依赖另一套引擎或另一个数据库客户端。

大记录自身是提交依据，不再另刷一个小通道索引来确认它。重启先验证两条日志并按全局提交序号合并，重建原有逻辑文件视图，再运行 Store 的正常恢复、索引与 WAL 校验。这样避免了一笔提交分别同步两个文件的问题。

逻辑文件用连续区间描述映射到日志位置。初版第二份完整文件缓冲已移除；大块不可变值在提交期间保留共享所有权并复用既有 CRC，直接写出，提交后区间指向持久化位置。小的键、头和数据先合并到最多 16 KiB 的编码块，避免 180 个小条目产生数百个多余的段描述。完整业务二进制缓存和减法裁剪保持原有实现，未为本测试添加自动差分。

每个 generation 在用户设置的数据库目录内只有同名的两条数据通道，例如 `g0000000000000001.fdb` 与 `g0000000000000001.blk`。没有增加子目录层级，文件名长度相同；.blk 是数据日志，不是诊断日志。两个文件的身份与 generation 必须匹配。大通道在新 generation 发布 CURRENT 前创建并同步，正常首次大事务不再临时创建目录项。

大小通道共用原子性与 SYNC 返回承诺，但介质损坏的冗余能力不同：小通道保留多副本恢复；大通道采用主引擎的单份追加加校验策略，损坏时拒绝打开并保留文件，不提供副本修复。没有将两者描述为相同的介质容错等级。

不完整末尾记录只有在长度不足以构成完整记录时才作为未完成尾部处理；完整记录校验错误、提交序号缺口或身份不匹配均拒绝。不是遇到 CRC 错误就删除日志。后续较短的大记录覆盖废弃尾部时会截断旧尾巴，避免放弃的数据复活。

## 性能证据

最终 `paired-report.json` 中，小记录各两轮、大批量各四轮，按交错顺序运行。编译、ASan/UBSan 与性能阶段分开；全部样本和重开结果均保留，没有覆盖慢样本。

| 负载 | 对照 | 新候选 | 结论 |
| --- | ---: | ---: | --- |
| 256 B 单条修改，每次同步 | retained2：2005 次/秒 | 2082 次/秒 | 保留原有水平，样本范围重叠 |
| 64 KiB × 32 条原子批量，每次同步 | 当前主引擎：7478 条/秒 | 8085 条/秒 | 本机短测回到同量级，算术均值约快 8.1% |

表中为各轮吞吐算术均值。按全部样本累计耗时计算，大批量分别为约 7458 与 8018 条/秒。每轮十二笔事务，共 24 MiB 业务值；两边都是十二次同步、780 次 pwrite。主引擎写入请求 25,187,724 B，新候选 25,213,356 B，额外约 0.10%。没有少同步或拆掉批量原子性来提速。

小记录区间：retained2 为 1850–2159 次/秒，新候选 2034–2129 次/秒。大批量区间：主引擎 7049–8047 条/秒，新候选 7260–9266 条/秒。不能由这些有限短样本承诺所有负载都达到峰值。

中间版本曾出现一次约 88 ms 的大提交，原日志保存在 `final-report.json`；最终代码修改并没有将其改写为成功快样本。最终配对样本独立保存；此前 `io2-report.json` 和 `validate-report.json` 的结果也有波动。当前结论是消除了原有大批量六倍左右的请求写放大，并达到主引擎同量级，不宣称消除操作系统和设备延迟尖峰。

单独移植连续描述的 `dense-report.json` 小记录基本持平，大批量未证明稳定收益。因此没有把最终路由收益全部归因于连续内存。

## 空间、包体与验证

同格式去整库缓冲版本实际打开 1000 个独立小库，每库一条 256 B 数据：.fdb 长度合计 69,632,000 B，两个通道及 CURRENT 等普通文件长度合计 69,835,000 B，普通文件实际分配合计 77,824,000 B，约 74.2 MiB。每个 .blk 初始长度仅 128 B，其文件系统分配会占一个块；没有每库或每事务预留 1 MiB。该测量在 `validate-report.json`，最终修改没有改变冷库文件结构。

小通道仍小起步、按需预留并默认保留扩容高水位；进程内新增预测余量默认共享 4 MiB，单文件预测上限可配置。大通道按实际记录顺序增长。共享预测额度不是关闭文件、跨进程重启后的持久化磁盘总配额。

最终 Linux 候选 744,888 B，比 retained2 增加 24,584 B，约 3.4%；Windows 候选 797,696 B。没有装入另一套完整引擎。额外通道解析、区间描述、合并恢复和研究诊断导出构成新增代码。

已完成的相关检查：

- 每个计时样本独立重开，核对完整值并调用 Store verify，16/32/180 条均可变。
- 同库小大事务交替、snapshot 旧视图、未提交事务关闭、checkpoint，确认原子值对不会出现一新一旧。
- 64 KiB 小缓存下 BUFFERED 大值借用，显式同步后重开保留；未同步关闭按合同允许丢失；检查共享值生命周期。
- 完整备份、恢复、在线整理及其后独立重开，两个通道随 generation 成对清理。
- 11 项恢复镜像：大日志从头、部分头、完整头、部分体、差一个尾字节到完整落盘；单份小副本损坏恢复；大记录损坏、跨通道中间提交缺失和双份小副本损坏均拒绝且文件哈希不变。
- 成功恢复后先继续小写、再以较短大记录覆盖废弃尾部、再次重开，未复活旧尾巴。恢复测试使用不同于创建时的阈值，恢复不依赖原阈值。
- Linux ASan/UBSan 覆盖混合路径、低缓存 BUFFERED、快照、备份/恢复/整理，无内存安全或未定义行为报告。
- Windows x64 构建并核对实际 DLL 加载路径，混合生命周期、默认阈值、16/180 条、独立重开通过；Windows 未作同等性能矩阵或系统调用计数。
- Linux/Windows 创建失败时，保留阻止 CREATE_NEW 的原有 .blk，仅清理本次新建的 .fdb，避免误删已有数据。

这是研究候选：逻辑视图和小日志仍有约 32 MiB 的研究边界；区间映射重建、生产受控缓存、分段及维护 I/O 预算还未完成集成。并发提交和读写混合的完整性能对照、设备级真实断电验证也未完成。分流层当前同步期间持锁，冷读写混合仍有优化空间。不能据此替换已有生产能力或声称完整发布验证。

## 证据与当前选择

选择以 retained2 衍生的按字节双通道候选继续集成研究；分离页头实验保留历史记录，不作为默认方向。主工作区源码仍与 `store-only-source-v6.json` 一致，未覆盖主库或 SDK。

证据目录：`build/arena-retained3-20261108/`。`dense-report.json` 为连续描述单项对照；`io-report.json` 是整库缓冲初版；`io2-report.json` 是连续区间映射；`validate-report.json` 保存交叉测试、混合生命周期、恢复及 1000 库空间；`final2-report.json` 为默认阈值、合并小片段、ASan/UBSan、恢复工具链及创建失败清理；`paired-report.json` 为最终配对性能；`windows-report.json` 为最终 Windows 运行。`final-report.json` 保留此前延迟尖峰，所有报告独立保存。

最终源码 `final2-manifest.json`；Linux 库 SHA-256 `accbb539a223ea7e7b30be0018b2fbb839ddc400424c123210d8611fbbc48544`；Windows 库 SHA-256 `a98ea3ddbac4a6ae43960f96c0b81c4b0bf55390c9e0c727cc58990c4ba78178`。所有本轮 Docker 容器和卷均核对随机所有权标签后清理，日志与源码快照保留。
