# 差分校验与同步往返优化审查（2026-11-09）

> 历史记录：本文保留当时的配置及测量数据；当前默认值已调整为 50 ms／1 MiB，见[写入策略](STORE_WRITE_POLICY.md)。

已接入主引擎，默认仍为性能模式、100 ms / 1 MiB。可靠模式及单次强制可靠确认仍在刷盘成功后返回。保留一个业务写线程，没有增加分片或流水线，也没有调整周期刷盘时持有写者的行为。公开 ABI 仍为 2，文件格式和 IEEE CRC32 校验算法不变。

## 实现

- 私有二进制缓冲复制时继承已有 CRC；等长覆盖只计算被替换段和新段的差分。追加只校验新增内容；变长编辑选择较短的前缀/后缀路线；大量删除后校验裁剪结果。小值和没有可用旧 CRC 的值继续走完整校验，避免固定计算成本导致回退。
- 复用 WAL 载荷校验组合整帧校验，省去可完整放入小缓冲的大帧的第二次主体扫描。跨块路径保持原实现。
- 同步完成使用 Linux futex / Windows WaitOnAddress；低排队量的性能请求最多等待 512 次 CPU pause，专用写线程在近期活跃时也保留同样有界窗口，然后交给系统休眠。多个请求排队及可靠请求不在调用方进行该活跃等待。其他平台和原生等待失败退回条件变量。异步凭据保留多等待者通知。
- 信号由每个调用线程复用，完成方持有独立共享所有权直至通知结束，保护调用线程提前退出和信号复用。原生完成后不再访问请求。写线程释放队列锁进行短暂等待后重新计算周期和配置，避免使用过期时机。

## 同批旧库 / 新库对照

Linux，固定 2 vCPU（CPU 0、2）、4 GiB、同一镜像与命名数据卷；每项每个库三次交替、每次计划 1 秒，每个调用线程一笔在途。表内为吞吐中位数，计入最终 sync，每次运行后独立重开校验完整业务字段。body 是业务正文长度，原生编码还含档案字段。该短测用于判断本轮机制，不替换历史跨数据库排名，也不能代表移动端磁盘表现。

## 1 MiB / 4 MiB 阈值

使用修改前基线库单独对照，周期均为 100 ms，8 个调用线程，三轮交替，包含最终 sync 和重开校验。默认值没有修改。

| body / 记录数 | 1 MiB 吞吐 | 4 MiB 吞吐 | 变化 | 刷盘次数中位数 | P99 微秒中位数 |
|---|---:|---:|---:|---:|---:|
| 4096 B / 4096 | 33,549 | 37,883 | +12.9% | 179 → 58 | 3400.2 → 2857.7 |
| 65536 B / 512 | 4,200 | 4,800 | +14.3% | 351 → 129 | 3637.9 → 7231.9 |

4 MiB 可以减少刷盘次数，提高本次两项整存吞吐；P99 的影响不一致，64 KiB 变差。因此保持可配置，不改默认。64 KiB / 4096 记录的准备过程返回 FQDB_LIMIT，未得到有效成绩；成功的 64 KiB 对照明确缩为 512 记录。基准准备事务现在按正文体积限制在约 4 MiB，避免一次固定塞入过多大记录。这不是超内存压力测试。

## 验证与包体

- Windows、Linux 各 25/25 原生测试通过，包括恢复、混合文件、写入策略、缓存及新增差分 CRC 测试。
- 两平台 C#、Java、Python 写策略与常规接口回归通过。
- ASan + UBSan + 泄漏检测、TSan 分别运行写策略、缓存/同步信号及差分 CRC 测试通过。覆盖原生等待不可用/失败、每线程信号复用、短线程退出和异步凭据多等待者。
- 新增正式测试含 60,000 次私有缓冲编辑对照，覆盖随机/非对齐编辑、变长修改、已知零 CRC、清空、大范围删除、保存点别名、可靠提交及两类文件重开。独立原型另有 60,000 组随机 CRC 对照；原型固定 4 KiB 修改 8 字节的 CRC 计算约 1,220 ns → 13 ns，只是校验计算而非整个数据库的倍数。
- Linux strip：826,832 → 830,928 B，增加 4,096 B（0.50%）。
- Windows DLL：853,504 → 860,160 B，增加 6,656 B（0.78%）。

CRC 逆移位表增加一次性约 8 KiB 内存；每个使用差分移位的线程有约 0.6 KiB 有界算子缓存。同步信号按调用线程复用，没有每次调用新建线程或通知对象。
